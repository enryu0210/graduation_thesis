앞으로의 연구·제안 실험은 아래 **두 축**으로 잡는다.

| 축 | 질문 | 대응 RQ · 기여 |
|---|---|---|
| **축 1 — 속도·정확도 교환 (T)** | 캐스케이드는 새 데이터셋·배포 조건에서 **같은 정확도를 얼마나 싸게** 얻는가? 그 교환 곡선을 어떻게 더 좋게 만드는가? | RQ5 전반 · 기여 C1(5.07배) |
| **축 2 — 넘김 판단 (G)** | 1차가 2차로 넘길 요청을 고르는 **게이트가 최적 라우터(oracle)에 얼마나 다가갈 수 있는가**? | RQ5 후반 · 기여 C4(14.8배 과잉 넘김) |

- ⚠️ **RQ 번호는 바꾸지 않는다.** 두 축은 이미 RQ5 문구("char-CNN 급 정확도를 얼마나 싸게 살 수 있으며, 그 게이트는 최적 라우터에 얼마나 근접하는가")에 들어 있다. 이 결정은 **새 질문이 아니라 노력 배분**이다.
- ⚠️ **HARKing 방지.** RQ1 의 음성 결과("이미지 단독은 텍스트 모델에 열세")는 그대로 보고한다. 초점을 RQ5 로 옮기는 이유는 "RQ1 이 음성이라서"가 아니라, **RQ1 음성이 곧 캐스케이드의 존재 이유**(마스터 §1.4)이고 그 이득이 아직 새 데이터에서 검증되지 않았기 때문이다.
- RQ2·RQ3·RQ6 의 기존 결과(2기)는 논문에 그대로 싣는다. 새 데이터셋에서의 확장은 **축 1·2 와 직접 닿는 부분만**(§4 G5 비용 기반 공격) 한다.

**읽는 법**
- 캐스케이드의 이득은 **"1차·2차의 비용 차 × 적게 넘기기"** 두 항의 곱이다. 축 1 은 첫 항과 곱 전체(배포 조건 포함)를, 축 2 는 둘째 항을 다룬다.
- 새 데이터에서는 **비용 차가 줄고 정확도 차가 커졌다** — 둘 다 캐스케이드에 불리하다. 5.07배보다 크게 낮게 나올 수 있다는 전제로 설계한다.
- 1차를 더 싸게 만드는 길은 M4 로 막혔다. 남은 지렛대는 **넘김을 줄이는 것(축 2)** 과 **2차를 싸게·1차를 약간 비싸게 하는 재배분(축 1 T3·T4)** 이다.

## 2. 공통 원칙 (모든 T·G 실험)

1. **τ·라우터·임계값은 val 에서 고르고 test 에 1회 적용**한다(기존 캐스케이드 원칙). 라우터를 학습하는 실험(G3)은 val 을 다시 쪼갠다 — §4.
2. **보고 축은 에스컬레이션 예산 곡선**이다(docs/13 §5 에서 RQ5 보고 축으로 채택). 단일 τ 한 점의 결과로 결론 내지 않는다.
3. 속도 배수에는 **2차 기준 모델 · 장치 · 배치 크기 · 공격 비율**을 반드시 병기한다(마스터 §11, 조건 없는 "N배" 금지).
4. 지연은 `cascade.measure_latency(sample_idx=...)` 로 **무작위 대표 배치**에서 잰다(앞 N개는 클래스 편향). E2 CV 의 처리량 수치는 판정에 쓰지 않는다.
5. 정확도 지표는 Macro-F1 · TPR@1%FPR · **실사용자 층 FPR**(`fpr_by_stratum`, docs/13 §4.1.2) 병기. 캐스케이드가 char-CNN 보다 **정확하다고 주장하지 않는다**(F4: 상보성 이득 없음).
6. GPU 1대 순차 실행. 긴 러너는 Bash 백그라운드 + 파일 로그로 띄운다.

## 3. 축 1 — 속도·정확도 교환 (T)

### T0 — 선행 조건 (두 축 공통)
- 트랙 입력 F3 전환 + 쿠키 공란화 ablation (CURRENT_BASELINE §8-4c)
- 양 끝점 체크포인트: RGB CNN · char-CNN (`--balance`) — RQ1 본 측정(§8-8)의 부분집합을 **먼저** 한다
- 1차 확률 포화 확인: `p1.max(1) == 1.0` 비율 (docs/13 §4.1.3 주의) → 크면 로짓 저장 경로 추가(코드 작업)

### T1 — 새 트랙 기준 교환 곡선 (C1 재측정)
- 예산 {0, 1, 2, 5, 10, 20, 30, 50, 100}% × Macro-F1 / TPR@1%FPR / 실사용자 층 FPR, **oracle 곡선 병기**
- 실측 지연 → `speedup_vs_stage2_only` · `overhead_vs_stage1_only` · **FE score**(`metrics.fe_score`, 지연 배선 필요 = 코드 작업)
- **배포 공격 비율 재가중**: test 의 클래스별 넘김률을 공격 비율 1% · 0.1% · 3.3% 로 재가중해 기대 지연·기대 속도 배수 산출(CURRENT_BASELINE §8-9)
- 판정 기준(초안): "char-CNN 대비 Macro-F1 −0.5pp 이내에서의 최대 속도 배수"를 공격 비율별로 보고. 배수가 **2배 미만**이면 C1 을 "조건부 이득"으로 하향하고 그 조건을 명시한다.

### T2 — 배포 조건별 지연 (장치 × 배치)
- 장치 {GPU, CPU} × 배치 {1, 32, 128, 1024} 에서 1차·2차·캐스케이드 지연
- 이유: 2기 13.6배 → E2 부산물 3.6배로 비용 차가 크게 달라졌다. 배치·장치에 따라 **속도 배수의 순위가 뒤집히는지** 먼저 알아야 T1 의 배수를 해석할 수 있다(단일 요청 WAF 는 배치 1·CPU 가 현실적).
- 판정 기준(초안): 조건별 배수를 표로만 보고(가설 검정 없음). 논문 헤드라인에 쓸 조건 1개를 **T1 실행 전에** 이 결과로 고정한다.

### T3 — 2차 모델 후보 (2차를 싸게)
- 2차 {char-CNN, BiLSTM, TF-IDF+LogReg} 각각으로 캐스케이드 조립 → 예산 곡선의 Pareto 비교
- 근거: TF-IDF+LogReg 는 CPU 에서 매우 싸고, 2026-09-15 코드 스모크(2-fold, F2 입력, **결과 파일 삭제됨 — 참고치**)에서 Macro-F1 약 0.94 였다.
  같은 F2 입력의 5-fold 값(RGB CNN 0.895 · char-CNN 0.990) 사이다. "싸고 적당한 2차"가 교환 곡선의 중간을 채울 수 있는지 본다(정식 CV 는 T0 의 RQ1 부분 측정에서).
- 판정 기준(초안): 어떤 예산에서든 char-CNN 2차 곡선을 **지배**(같은 지연에서 Macro-F1 이 CV paired adj p<0.05 로 높음)하면 대안 2차로 병기.

### T4 — 1차 용량 스윕 (1차를 약간 비싸게)
- RGB CNN 채널 폭 ×0.5 / ×1 / ×2 → 1차 비용 증가 vs 넘김 감소의 **순이득**
- 근거: M4 는 1차를 더 싸게 하는 방향이 이미 천장임을 보였다. 반대로 1차가 조금 비싸져도 넘김이 크게 줄면 전체는 빨라질 수 있다(1·2차 정확도 차가 커진 새 데이터에서 특히).
- 판정 기준(초안): T1 과 같은 "−0.5pp 이내 최대 속도 배수"가 ×1 대비 20% 이상 개선되면 1차 구성 변경을 제안한다. ⚠️ 새 이미지 모델 추가 시 `IMAGE_MODELS` 2곳 동기화.

## 4. 축 2 — 넘김 판단 (G)

**핵심 지표: 과잉 넘김 배율** = char-CNN 급 Macro-F1 도달에 필요한 넘김률 ÷ oracle 넘김률 (`gate_signals.over_escalation_ratio`). 2기 기준 14.8배.

### G1 — 게이트 신호 비교 (= docs/13 §4.1.3 E5 (가), 설계·판정 기준 기확정)
- msp / msp_T / margin / entropy. 판정 **H-E5-1**(과잉 넘김 배율 msp 대비 20%↓ + adj p<0.05 → C4 격상) 그대로. 도구 `src/models/gate_signals.py` 구현 완료.

### G2 — 클래스별 τ
- 1차 **예측 클래스마다** 별도 임계값(val 에서 전체 예산 제약 하 Macro-F1 최대화)
- 근거: 오답이 소수 클래스에 몰린다(E2: CmdI F1 이 약한 고리, RGB CNN F3 0.852). 단일 τ 는 다수 클래스(SQLi)의 확신도 분포에 끌려간다.
- 판정 기준(초안): H-E5-1 과 같은 형식(20%↓ · adj p<0.05). ⚠️ 클래스 수만큼 파라미터가 늘어나므로 val 과적합을 fold 간 τ 분산으로 함께 보고.

### G3 — 학습형 라우터
- 입력: 1차 확률(또는 로짓) + 값싼 입력 특징(길이·특수문자 비율 등) → 출력: "1차가 틀릴 확률". 모델은 로지스틱 회귀 수준의 경량 모델로 제한(라우터 비용이 1차 비용을 먹으면 무의미).
- ⚠️ **누수 방지**: 1차 학습에 쓴 데이터로 라우터를 학습하면 1차가 train 을 외워 "틀릴 확률"이 과소평가된다. val 을 **라우터 학습 / τ 선택** 절반으로 나누거나, 1차를 k-fold 로 학습해 out-of-fold 예측으로 라우터를 학습한다(착수 전 둘 중 하나로 확정).
- 라우터 추론 비용을 캐스케이드 지연에 **포함**한다.
- 판정 기준(초안): G1 최선 신호 대비 과잉 넘김 배율이 추가로 20%↓ 이고 지연 증가가 1차 비용의 10% 이내면 채택.

### G4 — τ 이식성 (= docs/13 §4.1.3 E5 (나) + 외부 세트)
- val 에서 예산 10% 로 고른 τ(또는 G2·G3 게이트)를 분포가 다른 세트에 적용 → **실현 넘김률과 목표의 차이**
- 세트: E1 세트(감사 적중 실공격, 학습 중복 760행 제외) · Data 2025(확보 시) · 실사용자 층 Normal
- 판정 **H-E5-2** 그대로. 게이트가 좋아져도 이식성이 나쁘면 운영 예산을 보장할 수 없다 — 축 1 의 배포 조건 배수(T1)와 함께 해석.

### G5 — 게이트의 비용 기반 공격 강건성 (F7 재측정)
- G1~G3 에서 채택된 게이트로 변형 공격 하 넘김 증가 배율을 msp 게이트와 비교
- 질문: 게이트가 **정교해질수록 넘김을 부풀리는 공격에 더 취약해지는가**(학습형 라우터는 입력 특징을 쓰므로 조작 표면이 늘어난다).
- ⚠️ `run_evasion.py` 는 `srbh_4class` 를 **의도적으로 지원하지 않는다**(`mutations.py` 가 `XSS` 라벨명에 묶임) → 라벨 매핑 코드 작업이 선행.
- 판정 기준(초안): 채택 게이트의 공격 하 넘김 증가 배율이 msp 대비 **1.5배 이상**이면 "게이트 개선의 대가"로 한계에 명시.

## 6. 진행 순서 (초안)

```
T0 (F3 전환·쿠키 ablation·양 끝점 학습·확률 포화 확인)
 → T2 (배포 조건 지연 — 헤드라인 조건 고정)
 → T1 (새 트랙 교환 곡선 + base rate 재가중 + FE 배선)
 → G1 → G2 → G3 (게이트 개선, 과잉 넘김 배율 추적)
 → T3 · T4 (2차 후보 · 1차 용량 — G 최선 게이트로 조립)
 → G4 (이식성) → G5 (비용 기반 공격)
```
- G 를 T3·T4 앞에 두는 이유: 넘김 판단이 바뀌면 교환 곡선 전체가 이동한다. 최선 게이트를 먼저 정해야 T3·T4 비교가 한 번으로 끝난다.
- 코드 작업(Codex 위임)이 필요한 곳: T0 트랙 전환 · 로짓 저장(필요 시) · FE 지연 배선 · T2 지연 스윕 스크립트 · G2 · G3 · T4 모델 폭 인자 · G5 라벨 매핑.

## 8. 결과 기록

(실험을 착수하면 여기에 T0 → … 순으로 판정 기준 확정본과 실측을 누적한다.)

### 8.1 판정 기준 확정본 (2026-10-04, 어떤 측정보다 먼저 기록)

**T0-a 쿠키 절제 (F3M).** E2 에서 F3(+cookie)가 RGB CNN 의 Macro-F1 을 올렸지만(0.8949 → 0.9323, adj p 0.0202),
CmdI 만 쿠키가 거의 항상 차 있어(99.4%, 다른 클래스 약 80%) **쿠키의 내용이 아니라 존재·길이**가 이득을 냈을 수 있다.
- 새 입력 `F3M` = F3 와 같되 쿠키 값을 **같은 길이의 `x` 문자열**로 바꾼 것(빈 쿠키는 빈 채로). 존재와 길이는 남고 내용만 사라진다.
- 실행: `cross_validate.py --model cnn --channels rgb --track srbh_4class --fields F3M --exclude-test` (E2 와 같은 sealed 풀·fold, 지문 `ba8611a906b32831`).
- 비교: Macro-F1, paired t-test 2쌍(F3 vs F3M, F3M vs F2), Holm 보정, α=0.05.
- 판정:
  - F3 > F3M 이 유의 → 쿠키 **내용**이 정보를 준다 → 트랙을 **F3 로 전환**.
  - 그 밖(차이 없음 또는 F3M ≥ F3) → 이득은 존재·길이로 설명된다 → 트랙은 **F2 유지**. char-CNN 이 F2 를 골랐고 TPR@1%FPR 도 F2 가 높다는 점과도 맞는다. F3 의 이득은 "형식 지름길" 관찰로 기록한다.
  - F3M > F2 가 유의하면 그 자체가 "길이·존재 지름길"의 직접 증거이므로 함께 적는다.
- F3 로 전환하는 경우: 빈 입력 제거·중복 제거·라벨 충돌 제거의 키는 **F2 로 유지**하고 `text_raw` 만 F3 로 바꾼다(같은 URI+body 가 쿠키만 달리해 train·test 에 갈라지는 누수 방지, 행·row_id·split 불변).

**T0-c 확률 포화.** 1차(RGB CNN, `_bal`) val 에서 `p1.max(1) == 1.0`(float32) 비율이 **5% 를 넘으면** G1 전에 로짓 저장 경로를 추가한다. 5% 이하면 확률 행렬로 진행한다.

**T2 헤드라인 조건 — 측정 전에 고정.** 원래 계획은 "T2 결과를 보고 T1 전에 고정"이었지만, 결과를 보고 고르면 유리한 조건을 고를 여지가 남는다. 그래서 측정 전에 **CPU · 배치 1** 로 고정한다(요청이 하나씩 들어오는 WAF 배치가 가장 현실적인 조건). 나머지 7개 조건(GPU·CPU × 1·32·128·1024)은 표로 병기한다.
- 배치 > 1 의 캐스케이드 지연은 `ms1 + r·ms2` 근사다(실제로는 넘겨진 소수가 더 작은 배치로 2차를 탄다). 표에 근사임을 적는다.

**T1 운영점과 판정.**
- 예산 {0, 1, 2, 5, 10, 20, 30, 50, 100}% 마다 τ 는 **val MSP 분위수**로 정하고 test 에 그대로 적용한다. test 에서 실현된 넘김률은 따로 적는다.
- 대표 운영점: val Macro-F1 이 char-CNN 단독 val Macro-F1 − 0.5pp 이상이 되는 **가장 작은 예산**.
- 공격 비율 재가중: test 의 정상/공격별 넘김률 r_N, r_A 로 r(π) = π·r_A + (1−π)·r_N 을 구하고, π ∈ {1%, 0.1%, 3.3%} 와 test 실제 비율에서 기대 지연·속도 배수를 낸다.
- 판정: 헤드라인 조건에서 대표 운영점의 char-CNN 대비 속도 배수가 **2배 미만**이면 C1 을 "조건부 이득"으로 낮추고 그 조건을 적는다. 캐스케이드가 char-CNN 보다 정확하다는 주장은 하지 않는다(§2-5).

**G1 게이트 신호.** H-E5-1 의 "5-fold paired" 를 그대로 지키려고 단일 test split 이 아니라 **sealed CV fold** 에서 잰다(test split 을 건드리지 않는다).
- 각 fold 에서 1차(RGB CNN)와 2차(char-CNN)의 fold-val·fold-test 확률을 저장한다(두 모델은 같은 fold·같은 내부 val 을 쓴다: fold 와 내부 분할이 라벨과 seed 에만 의존).
- 온도 T 는 fold-val 에서, 평가는 fold-test 에서 한다.
- 과잉 넘김 배율의 목표 = 그 fold 의 char-CNN 단독 Macro-F1. 어느 fold 에서든 `msp` 가 목표에 닿지 못하면 목표를 −0.5pp 로 낮춰 **모든 신호에 같은 목표**로 다시 잰다(낮춘 사실을 적는다).
- 검정: 신호 3개(msp_T, margin, entropy) 각각 vs msp, 배율에 paired t-test, Holm(3쌍). 배율 20% 이상 감소 **그리고** adj p < 0.05 면 H-E5-1 충족.
- 1차 입력 필드는 T0-a 판정을 따른다. 2차는 F2(E2 결정).

- 이유가 표에 그대로 있다: 네 신호의 test 순위 상관(Spearman, msp 기준)이 fold 마다 **0.997 이상**이다. 온도 T 가 0.99~1.06 으로 1 에 붙어 있어 msp_T 는 msp 와 사실상 같은 신호이고, 4클래스에서 margin·entropy 도 같은 순서를 낸다. **확신도를 어떻게 요약하든 "1차가 덜 확신하는 요청"이라는 같은 집합을 고른다.**
- 그 집합이 오라클이 고르는 집합(1차가 틀리고 2차가 맞는 요청, 6~8%)과 다르다는 것이 과잉 넘김 10.5배의 정체다. Jitkrittum et al.(NeurIPS'23) 의 "1차 확신도만 보는 규칙은 2차의 정오를 모른다"는 지적이 이 트랙에서 실측으로 성립한다(docs/12 §1.7).
- 2기 C4(14.8배)와의 관계: 같은 정의의 지표가 새 데이터·sealed CV 5 fold 에서 6.1~17.7배(평균 10.5배)로 재현됐다. 단 2기 값은 단일 split·MCC 목표였으므로 직접 비교는 "같은 자릿수"까지만.
- 다음 수: 신호 교체(G1)는 닫는다. 남은 지렛대는 (가) **Normal 넘김을 따로 줄이는 G2(클래스별 τ)** — 운영점 넘김의 다수가 Normal 이고 배포 비율에서는 r_N 이 곧 넘김률이다, (나) **G3 학습형 라우터**(Diff-01 타깃, Jitkrittum), (다) **T4 1차 강화** — 1차·2차 격차 17pp 가 넘김 50% 의 근본 원인이다.
