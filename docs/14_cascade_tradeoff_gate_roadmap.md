| 축 | 질문 | 대응 RQ · 기여 |
|---|---|---|
| **축 1 — 속도·정확도 교환 (T)** | 캐스케이드는 새 데이터셋·배포 조건에서 **같은 정확도를 얼마나 싸게** 얻는가? 그 교환 곡선을 어떻게 더 좋게 만드는가? | RQ5 전반 · 기여 C1(5.07배) |

- ⚠️ **RQ 번호는 바꾸지 않는다.** 두 축은 이미 RQ5 문구("char-CNN 급 정확도를 얼마나 싸게 살 수 있으며, 그 게이트는 최적 라우터에 얼마나 근접하는가")에 들어 있다. 이 결정은 **새 질문이 아니라 노력 배분**이다.
- ⚠️ **HARKing 방지.** RQ1 의 음성 결과("이미지 단독은 텍스트 모델에 열세")는 그대로 보고한다. 초점을 RQ5 로 옮기는 이유는 "RQ1 이 음성이라서"가 아니라, **RQ1 음성이 곧 캐스케이드의 존재 이유**(마스터 §1.4)이고 그 이득이 아직 새 데이터에서 검증되지 않았기 때문이다.
- RQ2·RQ3·RQ6 의 기존 결과(2기)는 논문에 그대로 싣는다. 새 데이터셋에서의 확장은 **축 1·2 와 직접 닿는 부분만**(§4 G5 비용 기반 공격) 한다.

**읽는 법**
- 캐스케이드의 이득은 **"1차·2차의 비용 차 × 적게 넘기기"** 두 항의 곱이다. 축 1 은 첫 항과 곱 전체(배포 조건 포함)를, 축 2 는 둘째 항을 다룬다.
- 새 데이터에서는 **비용 차가 줄고 정확도 차가 커졌다** — 둘 다 캐스케이드에 불리하다. 5.07배보다 크게 낮게 나올 수 있다는 전제로 설계한다.
- 1차를 더 싸게 만드는 길은 M4 로 막혔다. 남은 지렛대는 **넘김을 줄이는 것(축 2)** 과 **2차를 싸게·1차를 약간 비싸게 하는 재배분(축 1 T3·T4)** 이다.

## 2. 공통 원칙 (모든 T·G 실험)

1. **τ·라우터·임계값은 val 에서 고르고 test 에 1회 적용**한다(기존 캐스케이드 원칙). 라우터를 학습하는 실험(G3)은 val 을 다시 쪼갠다 — §4.
2. **보고 축은 에스컬레이션 예산 곡선**이다(docs/13 §5 에서 RQ5 보고 축으로 채택). 단일 τ 한 점의 결과로 결론 내지 않는다.
3. 속도 배수에는 **2차 기준 모델 · 장치 · 배치 크기 · 공격 비율**을 반드시 병기한다(마스터 §11, 조건 없는 "N배" 금지).
4. 지연은 `cascade.measure_latency(sample_idx=...)` 로 **무작위 대표 배치**에서 잰다(앞 N개는 클래스 편향). E2 CV 의 처리량 수치는 판정에 쓰지 않는다.
5. 정확도 지표는 Macro-F1 · TPR@1%FPR · **실사용자 층 FPR**(`fpr_by_stratum`, docs/13 §4.1.2) 병기. 캐스케이드가 char-CNN 보다 **정확하다고 주장하지 않는다**(F4: 상보성 이득 없음).
6. GPU 1대 순차 실행. 긴 러너는 Bash 백그라운드 + 파일 로그로 띄운다.

## 3. 축 1 — 속도·정확도 교환 (T)

### T0 — 선행 조건 (두 축 공통)
- 트랙 입력 F3 전환 + 쿠키 공란화 ablation (CURRENT_BASELINE §8-4c)
- 양 끝점 체크포인트: RGB CNN · char-CNN (`--balance`) — RQ1 본 측정(§8-8)의 부분집합을 **먼저** 한다
- 1차 확률 포화 확인: `p1.max(1) == 1.0` 비율 (docs/13 §4.1.3 주의) → 크면 로짓 저장 경로 추가(코드 작업)

### T1 — 새 트랙 기준 교환 곡선 (C1 재측정)
- 예산 {0, 1, 2, 5, 10, 20, 30, 50, 100}% × Macro-F1 / TPR@1%FPR / 실사용자 층 FPR, **oracle 곡선 병기**
- 실측 지연 → `speedup_vs_stage2_only` · `overhead_vs_stage1_only` · **FE score**(`metrics.fe_score`, 지연 배선 필요 = 코드 작업)
- **배포 공격 비율 재가중**: test 의 클래스별 넘김률을 공격 비율 1% · 0.1% · 3.3% 로 재가중해 기대 지연·기대 속도 배수 산출(CURRENT_BASELINE §8-9)
- 판정 기준(초안): "char-CNN 대비 Macro-F1 −0.5pp 이내에서의 최대 속도 배수"를 공격 비율별로 보고. 배수가 **2배 미만**이면 C1 을 "조건부 이득"으로 하향하고 그 조건을 명시한다.

### T2 — 배포 조건별 지연 (장치 × 배치)
- 장치 {GPU, CPU} × 배치 {1, 32, 128, 1024} 에서 1차·2차·캐스케이드 지연
- 이유: 2기 13.6배 → E2 부산물 3.6배로 비용 차가 크게 달라졌다. 배치·장치에 따라 **속도 배수의 순위가 뒤집히는지** 먼저 알아야 T1 의 배수를 해석할 수 있다(단일 요청 WAF 는 배치 1·CPU 가 현실적).
- 판정 기준(초안): 조건별 배수를 표로만 보고(가설 검정 없음). 논문 헤드라인에 쓸 조건 1개를 **T1 실행 전에** 이 결과로 고정한다.

### T3 — 2차 모델 후보 (2차를 싸게)
- 2차 {char-CNN, BiLSTM, TF-IDF+LogReg} 각각으로 캐스케이드 조립 → 예산 곡선의 Pareto 비교
- 근거: TF-IDF+LogReg 는 CPU 에서 매우 싸고, 2026-09-15 코드 스모크(2-fold, F2 입력, **결과 파일 삭제됨 — 참고치**)에서 Macro-F1 약 0.94 였다.
  같은 F2 입력의 5-fold 값(RGB CNN 0.895 · char-CNN 0.990) 사이다. "싸고 적당한 2차"가 교환 곡선의 중간을 채울 수 있는지 본다(정식 CV 는 T0 의 RQ1 부분 측정에서).
- 판정 기준(초안): 어떤 예산에서든 char-CNN 2차 곡선을 **지배**(같은 지연에서 Macro-F1 이 CV paired adj p<0.05 로 높음)하면 대안 2차로 병기.

### T4 — 1차 용량 스윕 (1차를 약간 비싸게)
- RGB CNN 채널 폭 ×0.5 / ×1 / ×2 → 1차 비용 증가 vs 넘김 감소의 **순이득**
- 근거: M4 는 1차를 더 싸게 하는 방향이 이미 천장임을 보였다. 반대로 1차가 조금 비싸져도 넘김이 크게 줄면 전체는 빨라질 수 있다(1·2차 정확도 차가 커진 새 데이터에서 특히).
- 판정 기준(초안): T1 과 같은 "−0.5pp 이내 최대 속도 배수"가 ×1 대비 20% 이상 개선되면 1차 구성 변경을 제안한다. ⚠️ 새 이미지 모델 추가 시 `IMAGE_MODELS` 2곳 동기화.

## 4. 축 2 — 넘김 판단 (G)

**핵심 지표: 과잉 넘김 배율** = char-CNN 급 Macro-F1 도달에 필요한 넘김률 ÷ oracle 넘김률 (`gate_signals.over_escalation_ratio`). 2기 기준 14.8배.

### G1 — 게이트 신호 비교 (= docs/13 §4.1.3 E5 (가), 설계·판정 기준 기확정)
- msp / msp_T / margin / entropy. 판정 **H-E5-1**(과잉 넘김 배율 msp 대비 20%↓ + adj p<0.05 → C4 격상) 그대로. 도구 `src/models/gate_signals.py` 구현 완료.

### G2 — 클래스별 τ
- 1차 **예측 클래스마다** 별도 임계값(val 에서 전체 예산 제약 하 Macro-F1 최대화)
- 근거: 오답이 소수 클래스에 몰린다(E2: CmdI F1 이 약한 고리, RGB CNN F3 0.852). 단일 τ 는 다수 클래스(SQLi)의 확신도 분포에 끌려간다.
- 판정 기준(초안): H-E5-1 과 같은 형식(20%↓ · adj p<0.05). ⚠️ 클래스 수만큼 파라미터가 늘어나므로 val 과적합을 fold 간 τ 분산으로 함께 보고.

### G3 — 학습형 라우터
- 입력: 1차 확률(또는 로짓) + 값싼 입력 특징(길이·특수문자 비율 등) → 출력: "1차가 틀릴 확률". 모델은 로지스틱 회귀 수준의 경량 모델로 제한(라우터 비용이 1차 비용을 먹으면 무의미).
- ⚠️ **누수 방지**: 1차 학습에 쓴 데이터로 라우터를 학습하면 1차가 train 을 외워 "틀릴 확률"이 과소평가된다. val 을 **라우터 학습 / τ 선택** 절반으로 나누거나, 1차를 k-fold 로 학습해 out-of-fold 예측으로 라우터를 학습한다(착수 전 둘 중 하나로 확정).
- 라우터 추론 비용을 캐스케이드 지연에 **포함**한다.
- 판정 기준(초안): G1 최선 신호 대비 과잉 넘김 배율이 추가로 20%↓ 이고 지연 증가가 1차 비용의 10% 이내면 채택.

### G4 — τ 이식성 (= docs/13 §4.1.3 E5 (나) + 외부 세트)
- val 에서 예산 10% 로 고른 τ(또는 G2·G3 게이트)를 분포가 다른 세트에 적용 → **실현 넘김률과 목표의 차이**
- 세트: E1 세트(감사 적중 실공격, 학습 중복 760행 제외) · Data 2025(확보 시) · 실사용자 층 Normal
- 판정 **H-E5-2** 그대로. 게이트가 좋아져도 이식성이 나쁘면 운영 예산을 보장할 수 없다 — 축 1 의 배포 조건 배수(T1)와 함께 해석.

### G5 — 게이트의 비용 기반 공격 강건성 (F7 재측정)
- G1~G3 에서 채택된 게이트로 변형 공격 하 넘김 증가 배율을 msp 게이트와 비교
- 질문: 게이트가 **정교해질수록 넘김을 부풀리는 공격에 더 취약해지는가**(학습형 라우터는 입력 특징을 쓰므로 조작 표면이 늘어난다).
- ⚠️ `run_evasion.py` 는 `srbh_4class` 를 **의도적으로 지원하지 않는다**(`mutations.py` 가 `XSS` 라벨명에 묶임) → 라벨 매핑 코드 작업이 선행.
- 판정 기준(초안): 채택 게이트의 공격 하 넘김 증가 배율이 msp 대비 **1.5배 이상**이면 "게이트 개선의 대가"로 한계에 명시.

## 6. 진행 순서 (초안)

```
T0 (F3 전환·쿠키 ablation·양 끝점 학습·확률 포화 확인)
 → T2 (배포 조건 지연 — 헤드라인 조건 고정)
 → T1 (새 트랙 교환 곡선 + base rate 재가중 + FE 배선)
 → G1 → G2 → G3 (게이트 개선, 과잉 넘김 배율 추적)
 → T3 · T4 (2차 후보 · 1차 용량 — G 최선 게이트로 조립)
 → G4 (이식성) → G5 (비용 기반 공격)
```
- G 를 T3·T4 앞에 두는 이유: 넘김 판단이 바뀌면 교환 곡선 전체가 이동한다. 최선 게이트를 먼저 정해야 T3·T4 비교가 한 번으로 끝난다.
- 코드 작업(Codex 위임)이 필요한 곳: T0 트랙 전환 · 로짓 저장(필요 시) · FE 지연 배선 · T2 지연 스윕 스크립트 · G2 · G3 · T4 모델 폭 인자 · G5 라벨 매핑.

### 8.1 판정 기준 확정본 (2026-10-04, 어떤 측정보다 먼저 기록)

**T0-a 쿠키 절제 (F3M).** E2 에서 F3(+cookie)가 RGB CNN 의 Macro-F1 을 올렸지만(0.8949 → 0.9323, adj p 0.0202),
CmdI 만 쿠키가 거의 항상 차 있어(99.4%, 다른 클래스 약 80%) **쿠키의 내용이 아니라 존재·길이**가 이득을 냈을 수 있다.
- 새 입력 `F3M` = F3 와 같되 쿠키 값을 **같은 길이의 `x` 문자열**로 바꾼 것(빈 쿠키는 빈 채로). 존재와 길이는 남고 내용만 사라진다.
- 실행: `cross_validate.py --model cnn --channels rgb --track srbh_4class --fields F3M --exclude-test` (E2 와 같은 sealed 풀·fold, 지문 `ba8611a906b32831`).
- 비교: Macro-F1, paired t-test 2쌍(F3 vs F3M, F3M vs F2), Holm 보정, α=0.05.
- 판정:
  - F3 > F3M 이 유의 → 쿠키 **내용**이 정보를 준다 → 트랙을 **F3 로 전환**.
  - 그 밖(차이 없음 또는 F3M ≥ F3) → 이득은 존재·길이로 설명된다 → 트랙은 **F2 유지**. char-CNN 이 F2 를 골랐고 TPR@1%FPR 도 F2 가 높다는 점과도 맞는다. F3 의 이득은 "형식 지름길" 관찰로 기록한다.
  - F3M > F2 가 유의하면 그 자체가 "길이·존재 지름길"의 직접 증거이므로 함께 적는다.
- F3 로 전환하는 경우: 빈 입력 제거·중복 제거·라벨 충돌 제거의 키는 **F2 로 유지**하고 `text_raw` 만 F3 로 바꾼다(같은 URI+body 가 쿠키만 달리해 train·test 에 갈라지는 누수 방지, 행·row_id·split 불변).

**T0-c 확률 포화.** 1차(RGB CNN, `_bal`) val 에서 `p1.max(1) == 1.0`(float32) 비율이 **5% 를 넘으면** G1 전에 로짓 저장 경로를 추가한다. 5% 이하면 확률 행렬로 진행한다.

**T2 헤드라인 조건 — 측정 전에 고정.** 원래 계획은 "T2 결과를 보고 T1 전에 고정"이었지만, 결과를 보고 고르면 유리한 조건을 고를 여지가 남는다. 그래서 측정 전에 **CPU · 배치 1** 로 고정한다(요청이 하나씩 들어오는 WAF 배치가 가장 현실적인 조건). 나머지 7개 조건(GPU·CPU × 1·32·128·1024)은 표로 병기한다.
- 배치 > 1 의 캐스케이드 지연은 `ms1 + r·ms2` 근사다(실제로는 넘겨진 소수가 더 작은 배치로 2차를 탄다). 표에 근사임을 적는다.

**T1 운영점과 판정.**
- 예산 {0, 1, 2, 5, 10, 20, 30, 50, 100}% 마다 τ 는 **val MSP 분위수**로 정하고 test 에 그대로 적용한다. test 에서 실현된 넘김률은 따로 적는다.
- 대표 운영점: val Macro-F1 이 char-CNN 단독 val Macro-F1 − 0.5pp 이상이 되는 **가장 작은 예산**.
- 공격 비율 재가중: test 의 정상/공격별 넘김률 r_N, r_A 로 r(π) = π·r_A + (1−π)·r_N 을 구하고, π ∈ {1%, 0.1%, 3.3%} 와 test 실제 비율에서 기대 지연·속도 배수를 낸다.
- 판정: 헤드라인 조건에서 대표 운영점의 char-CNN 대비 속도 배수가 **2배 미만**이면 C1 을 "조건부 이득"으로 낮추고 그 조건을 적는다. 캐스케이드가 char-CNN 보다 정확하다는 주장은 하지 않는다(§2-5).

**G1 게이트 신호.** H-E5-1 의 "5-fold paired" 를 그대로 지키려고 단일 test split 이 아니라 **sealed CV fold** 에서 잰다(test split 을 건드리지 않는다).
- 각 fold 에서 1차(RGB CNN)와 2차(char-CNN)의 fold-val·fold-test 확률을 저장한다(두 모델은 같은 fold·같은 내부 val 을 쓴다: fold 와 내부 분할이 라벨과 seed 에만 의존).
- 온도 T 는 fold-val 에서, 평가는 fold-test 에서 한다.
- 과잉 넘김 배율의 목표 = 그 fold 의 char-CNN 단독 Macro-F1. 어느 fold 에서든 `msp` 가 목표에 닿지 못하면 목표를 −0.5pp 로 낮춰 **모든 신호에 같은 목표**로 다시 잰다(낮춘 사실을 적는다).
- 검정: 신호 3개(msp_T, margin, entropy) 각각 vs msp, 배율에 paired t-test, Holm(3쌍). 배율 20% 이상 감소 **그리고** adj p < 0.05 면 H-E5-1 충족.
- 1차 입력 필드는 T0-a 판정을 따른다. 2차는 F2(E2 결정).

- 그 집합이 오라클이 고르는 집합(1차가 틀리고 2차가 맞는 요청, 6~8%)과 다르다는 것이 과잉 넘김 10.5배의 정체다. Jitkrittum et al.(NeurIPS'23) 의 "1차 확신도만 보는 규칙은 2차의 정오를 모른다"는 지적이 이 트랙에서 실측으로 성립한다(docs/12 §1.7).

- 다음 수: 신호 교체(G1)는 닫는다. 남은 지렛대는 (가) **Normal 넘김을 따로 줄이는 G2(클래스별 τ)** — 운영점 넘김의 다수가 Normal 이고 배포 비율에서는 r_N 이 곧 넘김률이다, (나) **G3 학습형 라우터**(Diff-01 타깃, Jitkrittum), (다) **T4 1차 강화** — 1차·2차 격차 17pp 가 넘김 50% 의 근본 원인이다.

### 8.5 G2 판정 기준 확정본 (2026-10-04, 어떤 측정보다 먼저 기록)

**질문.** 단일 τ 대신 1차 **예측 클래스마다** 임계값 τ_c 를 두면 과잉 넘김이 줄어드는가.
G1 운영점에서 클래스별 넘김률이 13.7%(CodeInj)~83.7%(CmdI)로 크게 갈렸으므로, 단일 τ 가 클래스마다 다른 확신도 분포에 맞지 않는다는 가설이다.

- **데이터**: G1 과 같은 CV 확률 두 파일(`cvprobs_srbh_4class_cnn_raw_rgb_sealed.npz`, `cvprobs_srbh_4class_charcnn_raw_sealed.npz`, 지문 `ba8611a906b32831`). 새 학습 없음. test split 은 쓰지 않는다.
- **G2 게이트**: 각 fold 의 fold-val 에서 탐욕적으로 고른다. 넘김을 val 행의 0.5% 단위로 늘리되, 매 단계 네 예측 클래스 중
  "그 클래스에서 다음으로 확신도가 낮은 0.5% 덩어리를 넘겼을 때 val 캐스케이드 Macro-F1 이 가장 높은 클래스"에 배정한다.
  예산마다 τ_c 4개가 나오고, 그대로 fold-test 에 적용한다. 신호는 msp(G1 에서 다른 신호가 같은 순위를 냈다).
  탐욕 탐색은 4차원 전수탐색의 근사이므로 G2 의 **하한**으로 해석한다.
- **비교 기준 B0**: 단일 τ msp, 같은 예산 격자에서 val 분위수로 τ 를 정해 fold-test 에 적용(T1 과 같은 방식).
  G1 의 msp 배수(test 순위 직접 사용)와 달리 B0·G2 는 둘 다 **val→test 이식**을 거친다 — 같은 조건에서 비교하기 위해서다. G1 배수는 참고로만 병기한다.
- **지표**: 예산 격자(0~100%, 0.5% 간격)에서 fold-test Macro-F1 ≥ 목표(그 fold 의 char-CNN 단독 test Macro-F1)가 되는 **실현 test 넘김률의 최소값** ÷ 오라클 넘김률 = 과잉 넘김 배율.
  B0 가 어느 fold 에서든 목표에 닿지 못하면 G1 과 같이 목표를 −0.5pp 로 낮춰 **두 게이트 모두** 다시 잰다.
- **검정·판정 H-G2**: 배율에 5-fold paired t-test(비교 1쌍이라 Holm 없음). **감소율 ≥ 20% 그리고 p < 0.05** 면 채택 → 논문의 "개선" 결과로 쓴다. 그 밖은 기각.
- **부가 보고(판정에 쓰지 않음)**:
  - 운영점: 각 게이트에서 val Macro-F1 ≥ char-CNN val Macro-F1 − 0.5pp 가 되는 최소 예산 → test 넘김률·Macro-F1·정상 행 넘김률 r_N·공격 행 넘김률 r_A.
  - 배포 배수: T2 의 CPU·1 실측(ms1 0.350, ms2 1.114)에 r(π) = π·r_A + (1−π)·r_N 을 넣어 π ∈ {fold 실제 비율, 3.3%, 0.1%} 에서 계산. T2 는 단일 split 모델의 측정이므로 근사다.
  - 과적합 점검: 운영점 τ_c 의 fold 간 평균·표준편차, val 넘김률과 test 넘김률의 차이.
- **해석 경계**: 채택되더라도 G1 결론("확신도 신호를 바꾸는 것으로는 안 된다")은 그대로 둔다. 추가되는 문장은 "같은 신호라도 클래스별로 예산을 나누면 X% 준다"이다.

**결론.** 개선 축의 사전 판정은 음성이다(G1·G2 모두 기각). 다만 G2 는 실용 운영점에서 넘김 −7.6pp(정상 −17pp)·배포 배수 1.34 → 1.75배라는 일관된 효과를 보여, "확신도 신호는 그대로 두고 예산을 클래스별로 나누는 것"이 G1 의 신호 교체보다 유망하다는 방향 근거가 된다. 확정 주장으로 올리려면 운영점 넘김률을 1차 지표로 하는 별도 사전 등록과 외부 세트(G4) 재현이 필요하다.

### 8.7 과잉 넘김의 원인 분석 (2026-10-04, 탐색 — 판정 아님)

G1·G2 가 둘 다 기각된 뒤, 무엇을 고쳐야 넘김이 줄어드는지 보려고 CV 확률(§8.4 와 같은 두 파일)을 풀 전체 out-of-fold 로 모아 분석했다.
세션 스크래치 스크립트로 계산했고 커밋하지 않았다(아래 수치는 두 cvprobs 파일 + `cross_validate.load_text_pool(..., exclude_test=True)` 로 재현 가능). **이 분석은 CV 데이터를 라우터 탐색에 이미 썼으므로, §8.8 의 확인 실험은 고정 split test 로 한다.**

- **결과 2×2 (226,048행)**: 1차 오답 6.82%, 2차 오답 0.56%. 넘기면 고쳐지는 행(1차 오답·2차 정답) 6.40%, 넘기면 망가지는 행(1차 정답·2차 오답) 0.14%, 둘 다 오답 0.42%.
  클래스별 F1 은 1차 CodeInj 0.981 / CmdI 0.756 / Normal 0.889 / SQLi 0.952, 2차 0.998 / 0.968 / 0.991 / 0.996.
- **MSP 는 오답 순위를 잘 매긴다**(1차 오답 AUROC 0.938). 고칠 수 있는 오답의 91% 가 MSP<0.9 이고 MSP≥0.99 는 0.8% 뿐이다 → "확신하는 오답"은 주원인이 아니다.
- **꼬리 문제다.** MSP 순으로 넘길 때 고칠 수 있는 오답을 50%/80%/90%/95%/99% 회수하려면 넘김이 7.4%/14.2%/18.7%/23.4%/33.4% 필요하다. 목표가 char-CNN 단독 F1 이면 마지막 몇 % 가 넘김을 결정한다.
- **낭비 넘김의 절반이 정상 요청이다.** MSP 하위 25% 를 넘기면 넘긴 행의 74% 는 이미 1차가 맞힌 행이고, 그중 53% 가 실제 Normal 이다(Normal 은 전체의 25%). 1차가 맞힌 행의 MSP 중앙값은 Normal 0.970 · 공격 1.000 · 실사용자 층 Normal 0.870 — 실사용자 정상의 69% 가 25% 운영점에서 넘어간다.
- **Macro-F1 민감도**: 오답 1건을 고칠 때의 Macro-F1 이득이 CmdI·CodeInj 가 SQLi·Normal 의 약 6배다(소수 클래스). 균일 예산은 이득이 작은 곳에 넘김을 쓴다.
- **확신 높은 오답(MSP≥0.99, 고칠 수 있음, 약 107행)에는 라벨 의심 사례가 보인다** — 예: Normal 라벨의 `() { :;}; /bin/sleep 15`, SQLi 라벨의 `;cat /etc/passwd`.
- **라우터 상한 탐색**(fold-val 학습 → fold-test 순위, G1 과 같은 배율 정의): MSP 10.53 · 1차 확률만 쓴 HistGB 9.74 · 1차 확률+값싼 입력 통계 HistGB **7.57(−28%, 4/5 fold 감소)**.

**이론적 해석.** 2차가 거의 완벽하면 최적 넘김 규칙(Jitkrittum 류 "2차가 맞힐 확률 − 1차가 맞힐 확률 > c")은 "1차가 틀릴 확률 > c′"로 줄어든다 — 문제는 **고재현율 오답 탐지**다.
1차 확률 p1 의 어떤 함수도(G1 신호 교체, G2 클래스별 τ, p1 만 쓰는 라우터) 데이터 처리 부등식에 따라 p1 이 가진 정보를 넘을 수 없다. 그래서 개선은 (a) p1 밖의 정보(입력 통계·1차 내부 표현)를 쓰거나 (b) 1차 자체를 강하게 해 겹침을 줄이는 쪽이어야 한다.
라우터 비용 제약: S = t2/(t1 + t_r + r·t2) 에서 라우터가 CPU·1 에서 약 0.09ms 를 넘으면 넘김을 줄여도 손해다(T2 실측 기준).

### 8.8 확인 실험 판정 기준 확정본 (2026-10-04, 어떤 측정보다 먼저 기록)

§8.7 에서 나온 방향을 네 실험으로 확인한다. 진행 순서 1 → 4 → 3 → 2.

**실험 1 — G3-lite 와 G2 의 고정 split 확인 (H-G3L, H-G2c)**
- 데이터: T1 이 저장한 고정 split 확률 `tradeoff_probs_srbh_4class_cnn_raw_rgb_bal_..._b1-32-128-1024.npz`(1차 RGB CNN `_bal`, 2차 char-CNN `_bal`, val·test 각 39,891행) + 같은 순서의 val/test CSV 원문(행 순서·라벨 일치를 검사). 새 학습 없음.
- 게이트 3종, 모두 val 에서 고르고 test 에 1회 적용, 예산 격자 0.5%:
  - **B0**: 단일 τ msp(val 분위수 → test).
  - **G2**: §8.5 의 탐욕 클래스별 τ(`gate_signals.classwise_tau_path`) 그대로.
  - **G3-lite**: 로지스틱 회귀 라우터(표준화, C=1.0, 클래스 가중 없음). 입력 = 1차 확률 4개 + MSP + 1·2위 확률 차 + 원문 통계 5개(log1p(바이트 길이), 특수문자 `%'"<>();=&|$`{}` 비율, `%` 비율, 숫자 비율, 2304바이트 초과 여부(1차 이미지가 잘리는 행)). 표적 = "1차 오답 그리고 2차 정답". 점수가 높은 행부터 넘긴다.
    val 을 라벨 층화로 반씩(seed 42) 나눠 서로 교차 적합한 점수로 val 곡선·임계값을 정하고, test 점수는 두 반쪽 모델의 확률 평균이다(같은 모델 집합이 val·test 를 채점하게 하려는 것).
- 운영점: val Macro-F1 ≥ char-CNN val Macro-F1 − 0.5pp 인 점 중 val 넘김률 최소(§8.6 과 같은 규칙).
- **판정(각각 B0 대비)**: test 넘김률이 **5pp 이상 감소** 그리고 test 행 부트스트랩(2,000회, seed 42, 임계값 고정) 넘김률 차이 95% CI 상한 < 0 그리고 test Macro-F1 손실 ≤ 0.3pp → 채택. G2 는 H-G2c, G3-lite 는 H-G3L. 두 검정이라 각 결론을 따로 쓴다(서로의 채택 근거로 쓰지 않음).
- 라우터 지연: 특징 추출 + 내적(numpy)을 CPU·배치 1 로 2,000 요청 중앙값 측정해 S 에 포함. **t_r ≤ 0.035ms(1차의 10%)** 를 넘으면 "넘김은 줄지만 비용 조건 미달"로 기록한다.
- 부가 보고: 과잉 넘김 배율(test F1 ≥ char-CNN test F1, 미도달이면 −0.5pp), r_N·r_A, 배수 3종(π=test 실제·3.3%·0.1%, T2 CPU·1 ms 0.350/1.114 사용), 실사용자 층 넘김률(⚠️ 고정 split test 의 실사용자 정상은 95행이라 참고만).
- 한계: `_bal` 1차는 val 로 에폭을 골라 val 확률이 약간 낙관적이다(세 게이트에 공통).

**실험 4 — 꼬리 라벨 감사 (서술, 가설 검정 없음)**

- 두 집합을 섞어 **집단·모델 예측을 가린 채** 원문과 라벨만 보고 판정: 라벨 맞음 / 의심 / 틀림(+짧은 근거). 판정자는 Claude(LLM)이며 전문가 감사가 아님을 함께 적는다.
- 판정은 재생성할 수 없으므로 결과 CSV 를 `docs/audit/` 에 추적한다. 보고: 두 집합의 "의심+틀림" 비율과 그 차이(Fisher 정확 검정은 참고값).
- 해석 경계: 대상 집합의 비율이 대조보다 높으면 "확신 오답의 일부는 라벨 잡음"이라고 쓰되, §8.7 에서 이 행들이 넘김의 주원인이 아님을 함께 쓴다.

**실험 3 — T4 ① 1차 학습 방식 (H-T4a)**
- 고정 split 에서 RGB CNN 을 **class weight 비균형**(`--balance` 없음, CV 와 같은 방식)으로 학습하고, 2차는 기존 char-CNN `_bal` 을 그대로 둬 1차 효과만 분리한다. T1·T2 와 같은 도구(`cascade_tradeoff.py`, 같은 예산 격자·운영점 규칙)로 다시 잰다.
- **판정**: CPU·1 헤드라인 배수(π=3.3% 재가중)가 `_bal` 1차(T1, 0.99배) 대비 **20% 이상 개선(≥1.19)** 그리고 운영점 test Macro-F1 이 T1(0.9814) − 0.3pp 이상 → "1차를 class weight 로 학습하는 것"을 권장 구성으로 바꾼다. 단일 split·단일 seed 의 서술 결과임을 함께 쓴다.
- 부가: 같은 확률로 실험 1 의 세 게이트를 0.5% 격자에서 다시 잰다(판정에 쓰지 않음).
- **② (격자 배치 변경, 예: 12×192)는 하지 않는다**: 요청 중앙값이 87B 라 48×48 의 대부분이 빈칸인 것은 사실이지만, 이미지 정의를 바꾸면 RQ1·RQ2 의 모든 결과가 다른 입력 위에 서게 된다. 향후 과제로 남긴다.

**실험 2 — G3-full: 1차 내부 표현을 쓰는 넘김 헤드 (H-G3F, H-G3F-cv)**
- 1차 RGB CNN 을 얼린 채 GAP 뒤 128차원 표현을 뽑아, 실험 1 의 G3-lite 특징에 붙인 로지스틱 회귀 라우터(같은 표적·같은 교차 적합·같은 정규화 설정). 추가 비용은 128차원 내적 하나다.
- **고정 split(H-G3F)**: 실험 1 과 같은 `_bal` 체크포인트·같은 판정(B0 대비 −5pp · CI 상한<0 · F1 손실 ≤0.3pp). G3-lite 대비 넘김률 차이 CI 는 부가 보고.
- **CV(H-G3F-cv)**: RGB CNN CV(`--exclude-test`)를 표현 저장을 켜서 다시 돌리고, 2차는 기존 char-CNN cvprobs 를 쓴다(라벨 지문 일치 검사). fold 마다 fold-val 에서 라우터 적합 → fold-test. 지표는 §8.5 의 과잉 넘김 배율, 비교는 새 실행 확률로 다시 잰 B0.
  **판정: 감소율 ≥ 20% 그리고 paired t p < 0.05.** G3-lite 의 CV 배율도 함께 보고하되, 그 특징은 §8.7 에서 같은 CV 로 골랐으므로 탐색 값으로 표시한다.

| 실험 | 가설 | 판정 | 한 줄 |
|---|---|---|---|
| 1 | H-G2c(고정 split 클래스별 τ) | 채택 | 넘김 −8.8pp. 단 `_bal` 1차 위에서는 정상 넘김이 늘어 배포 0.99배 |
| 1 | H-G3L(원문 통계 라우터) | 기각 | −0.7pp, 정상 98% 넘김 |
| 4 | (서술) 꼬리 라벨 감사 | — | 확신 오답 70.9% vs 대조 31.8% 가 라벨 불일치 |
| 3 | H-T4a(1차 class weight) | **채택** | 공격 3.3% 배포 배수 0.99 → 1.45배, F1 0.9798 |
| 2 | H-G3F(고정 split 표현 라우터) | 채택 | −6.7pp, 단 배포 0.91배(정상 넘김 증가) |

- 넘김 판단 쪽 가설은 판정 기준을 통과해도(H-G2c·H-G3F) 정상 넘김을 늘리면 배포 속도가 나빠진다. **게이트 평가는 π 재가중 넘김률(r_N)을 함께 봐야 한다**는 것이 이번 확인 실험의 방법론적 결론이다.
- 과잉 넘김 배율(꼬리 기준)은 어떤 신호·라우터로도 유의하게 줄지 않았다(G1·G2·G3 모두 기각). 꼬리의 상당수가 라벨 잡음이라는 감사 결과와 함께, 논문에서는 "배율은 게이트의 한계라기보다 목표(2차 단독 F1)의 꼬리가 잡음을 포함하기 때문일 수 있다"를 한계·논의로 쓴다(주장 아님).
- C1 문구: "조건부 이득" 유지. SR-BH 헤드라인 값은 권장 구성(class weight 1차)으로 **CPU·1 1.67배(test 비율), 공격 3.3% 1.45배** 를 쓰고, 기존 1.22·0.99배(`_bal`)는 학습 방식 비교로 병기한다.

### 8.14 G6 · 남은 실험 판정 기준 확정본 (2026-10-07, 어떤 측정보다 먼저 기록)

**배경 — 왜 "넘김 점수"를 다시 바꾸나.** 지도교수 피드백: "넘김 판단에 쓰는 수치가 맞지 않는 것일 수 있다". G1(§8.4)은 msp_T·margin·entropy 를 시험했지만 네 신호의 순위 상관이 0.997 이상이라 **같은 수치를 다르게 요약한 것**이었고, §8.7 은 1차 확률 p1 의 어떤 함수도 p1 의 정보를 넘을 수 없다고 정리했다.
그래서 이번에는 **p1 이 아니라 1차의 내부 표현(GAP 128차원) 공간에서 재는 수치**로 바꾼다. G3-full(§8.12)도 이 표현을 썼지만 학습형 라우터(표적에 맞춰 적합)였다. G6 은 **학습 없는 거리 점수**이고, 문헌에서 확신도의 대안으로 제안된 것 네 개를 그대로 가져온다(새 점수를 만들지 않는다 — 사후 설계 방지).
선행 근거의 방향은 불리하다: Jaeger et al.(ICLR'23)은 오분류 탐지에서 MSP 가 대부분의 OOD 점수보다 강하다고 보고했다. 음성 결과도 "교수 지적의 직접 검증"으로 그대로 보고한다.

**G6 — 특징 공간 거리 기반 넘김 점수 (H-G6, H-G6f)**
- 표현 z: 1차 RGB CNN 의 GAP 출력(dropout 전, `extract_embeddings.py` 와 같은 정의). ŷ = 1차 argmax.
- 참조 집합 R: **그 모델을 학습한 train 행의 표현과 라벨**(CV 는 fold 내부 train, 고정 split 은 train split). val·test 는 참조에 쓰지 않는다.
- 점수(클수록 넘김) 네 개:
  - `maha` (Lee et al., NeurIPS'18): 클래스 평균 μ_c, 공유 공분산 Σ(클래스 중심화 후 Ledoit–Wolf 수축). 점수 = min_c (z−μ_c)ᵀΣ⁻¹(z−μ_c). 입력 전처리·층 앙상블은 쓰지 않는다(비용).
  - `rmaha` (Ren et al., 2021 Relative Mahalanobis): 위 D_c 에서 R 전체 단일 가우시안(Ledoit–Wolf)까지의 거리 D_0 을 뺀다. 점수 = min_c (D_c − D_0).
  - `knn` (Sun et al., ICML'22): L2 정규화 표현, 참조 뱅크 B = R 에서 클래스마다 2,000행 무작위(seed 42, 클래스 행이 더 적으면 전부). 점수 = B 안의 k=50 번째 최근접 거리.
  - `trust` (Jiang et al., NeurIPS'18 Trust Score, α-필터 미사용): L2 정규화 표현, 같은 뱅크를 클래스별 B_c 로 나눔. d_c = B_c 안의 최근접(k=1) 거리. trust = min_{c≠ŷ} d_c / max(d_ŷ, 1e-12). 점수 = −trust.
- 비교 기준 B0 = msp 단일 τ. 모든 게이트는 **val 에서 τ 를 고르고 test 에 1회 적용**: 예산 격자 0.005, τ = val 점수 분위수, 운영점 = val Macro-F1 ≥ char-CNN val Macro-F1 − 0.5pp 인 점 중 val 넘김률 최소(§8.6 규칙).
- **1차 지표(§8.9 의 교훈 반영)**: 운영점의 **배포 재가중 넘김률 E_π = π·r_A + (1−π)·r_N, π = 0.033**(test 에서 잰 r_N·r_A). 배포 배수 S = t2/(t1 + t_s + E_π·t2)(T2 CPU·배치1 0.350/1.114ms) 와 단조 관계라 속도 지표와 같은 판정이 된다.
- **H-G6 (CV, 판정)**: 1차 class weight(CV 기본) RGB CNN 을 `--exclude-test --save-probs --save-embeddings` + train 표현 저장으로 다시 돌리고, 2차는 기존 char-CNN cvprobs(지문 `ba8611a906b32831` 일치 검사). 점수마다 B0 대비
  ① fold 평균 E_π 상대 감소 ≥ 20% ② fold E_π 의 paired t-test, **Holm(4쌍)** 보정 p < 0.05 ③ fold 평균 test Macro-F1 손실 ≤ 0.3pp ④ 점수 지연 t_s(CPU·배치1, 1차 표현은 이미 있다고 보고 점수 계산만, 2,000요청 중앙값) ≤ 0.035ms(1차의 10%)
  → 넷 다 충족 시 채택. ①~③ 충족·④ 미달이면 "넘김은 줄지만 비용 조건 미달"로 기록한다.
- **H-G6f (고정 split, 확인)**: 권장 구성(1차 `srbh_4class_cnn_raw_rgb.pt` class weight + 2차 `_bal` char-CNN, T1 `_s2bal` 확률). 같은 운영점 규칙. test 행 부트스트랩 2,000회(seed 42, 임계값 고정)로 E_π 차이 95% CI 상한 < 0 그리고 상대 감소 ≥ 20% 그리고 test Macro-F1 손실 ≤ 0.3pp.
  **논문에 "개선"으로 쓰려면 H-G6 과 H-G6f 를 둘 다 충족해야 한다.** CV 에서 기각된 점수의 고정 split 값은 참고로만 적는다.
- 부가 보고(판정 아님): 과잉 넘김 배율(§8.5 정의, val→test 이식), test 넘김률·r_N·r_A, S(π = test 실제·3.3%·0.1%, t_s 포함), 1차 오답 탐지 AUROC(점수 vs 1차 오답), 점수와 msp 의 Spearman 상관(G1 처럼 같은 집합을 고르는지 확인).
  탐색: 각 점수에 클래스별 τ(`classwise_tau_path`)를 얹은 운영점. 이 값은 판정에 쓰지 않는다.

**G4 — 넘김률의 실사용자 이식성 (H-G4, 재정의)**
- 원 설계(H-E5-2)는 온도 보정이 τ 이식성을 개선하는지였는데, G1 에서 T 가 0.99~1.06 으로 1 에 붙어 있어 **질문 자체가 공허해졌다**(기록). 대신 배포 배수의 전제를 검사한다:
  val 의 정상은 96% 가 스캐너 층이다(§8.7). 배포 트래픽의 정상은 실사용자인데, val 에서 잰 r_N 이 실사용자에게도 성립하는가.
- 데이터: H-G6 과 같은 CV fold-test(풀 전체 out-of-fold, 실사용자 정상 550행), 층은 `load_pool_strata(exclude_test=True)`.
- 게이트: B0, G2(클래스별 τ, msp), H-G6 채택 점수(없으면 E_π 가 가장 낮은 점수를 참고로).
- 지표: fold 마다 gap = r_N(실사용자, fold-test) − r_N(정상 전체, fold-val).
- **판정(B0 기준)**: 5 fold 평균 gap ≥ +10pp 그리고 one-sample t p < 0.05 → "val 기반 배포 배수는 실사용자 트래픽에서 낙관적"으로 쓰고, 논문의 배포 배수에 **실사용자 보정 배수**(r_N 을 실사용자 층 값으로 바꾼 S)를 병기한다. 미충족이면 "이식된다(이 표본 규모에서)"로 쓴다. 게이트 간 gap 비교는 서술만.
- 고정 split 부가: E1-a 세트 중 트랙과 겹치지 않는 행(`overlap_split == ""`)에 권장 구성을 적용해 실현 넘김률과 cascade 공격 판정률을 서술로 보고한다(라벨상 정상이지만 실제로는 공격 탐침인 분포 이동 세트).

**T4b — 1차 폭 스윕 (H-T4b)**
- RGB CNN 채널 폭 ×0.5 · ×2 를 고정 split 에서 class weight(§8.11 과 같은 30에폭·best 에폭 선택)로 학습하고, 2차 `_bal` char-CNN 과 T1 도구로 다시 잰다(지연 실측 포함). tag 에 폭 축을 넣는다(×1 은 접미사 없음 → 기존 파일 호환).
- 게이트: B0(판정) + G2 · H-G6 채택 점수(부가).
- **판정**: 폭 w 의 S(π=3.3%, CPU·1) 가 ×1(§8.11 의 1.448, 같은 실행에서 다시 재면 그 값)보다 **20% 이상 크고** 운영점 test Macro-F1 ≥ ×1 운영점 − 0.3pp → 1차 폭 변경을 권장한다. 단일 split·단일 seed 서술 결과임을 함께 쓴다.

**T3 — 2차 후보 (H-T3, 서술 판정)**
- 2차 {char-CNN `_bal`(기준), BiLSTM `--balance`, TF-IDF+LogReg(`baseline_tfidf.py`, class_weight balanced)} 를 고정 split 에서 권장 1차와 조립한다. 2차 지연은 CPU·배치1 로 실측(TF-IDF 는 변환+예측 포함).
- 각 2차마다 예산 격자의 (π=3.3% 기대 지연, test Macro-F1) 곡선을 그린다.
- **판정**: 후보 곡선의 어떤 점이 char-CNN 곡선보다 **지연이 같거나 작으면서** test Macro-F1 이 높고, 그 F1 차이의 부트스트랩 95% CI(2,000회) 하한 > 0 이면 "대안 2차로 병기". 아니면 char-CNN 유지. (원 초안의 CV paired 비교는 2차 세 개의 CV 를 새로 돌려야 해서 고정 split 서술로 낮춘다 — 낮춘 사실을 기록.)

**G5 — 게이트의 넘김 부풀리기 강건성 (H-G5)**
- `mutations.py` 의 변형을 SR-BH 라벨에 매핑한다: SQLInjection → 공통+SQLi 전용, CommandInjection → 공통+CmdI 전용, CodeInjection → 공통만(XSS 전용 변형은 쓰지 않는다). `run_evasion.py` 는 건드리지 않고 별도 스크립트로 한다.
- 고정 split test 의 **공격 행 전부**에 각 단일 변형을 F2 원문 전체(URI+body)에 적용(seed 42)한다. 변형이 원문을 바꾸지 않은 행은 그 변형의 집계에서 뺀다. ⚠️ 원문 전체에 적용하므로 일부 변형은 HTTP 의미를 보존하지 않는다(problem-space 타당성 한계로 명시).
- 운영점(clean val 에서 고른 τ)은 **고정**하고 재튜닝하지 않는다.
- 지표: 게이트별 넘김 증가 배율 = r_A(변형) / r_A(원본), 변형별 + 변형 평균. 함께 cascade 공격 판정률(Normal 이 아닌 예측 비율).
- **판정**: 채택 게이트(H-G6 채택 점수, 없으면 G2)의 변형 평균 증가 배율이 B0 의 **1.5배 이상**이면 "게이트 개선의 대가"로 한계에 쓴다. 미만이면 "개선 게이트가 비용 기반 공격면을 넓히지 않았다(이 변형 집합에서)".

**실행 순서**: G6(CV → 고정 split) → G4 → T4b → T3 → G5. 각 실험의 게이트 집합은 앞 실험의 판정을 따른다. 결과는 §8.15 부터 누적한다.

**왜 거리 점수가 지는가 (해석 — 주장 아님)**
- maha 의 오답 AUROC 0.20 은 **역방향**이다: 1차가 틀리는 행이 오히려 클래스 평균에 가깝다. 오답이 "학습 분포 밖"이 아니라 **클래스 덩어리가 겹치는 한가운데**에 있다는 뜻이다. 꼬리 라벨 감사(§8.13: 확신 오답의 70.9% 가 라벨 불일치)와 같은 그림 — Normal 라벨이 붙은 스캐너 탐침은 공격 덩어리 안에 있다. OOD 점수는 이런 오답을 원리상 못 잡는다.
- 이는 Jaeger et al.(ICLR'23)의 "오분류 탐지에서는 MSP 가 OOD 점수보다 강하다"와 같은 방향이다.
- **교수 지적("넘김 판단 수치가 맞지 않을 수 있다")의 직접 답**: p1 함수(G1)와 표현 거리(G6) 모두 msp 보다 오답 순위를 잘 매기지 못했다. 이 데이터에서 **점수(무엇으로 재는가)는 병목이 아니다.** 남은 여지는 임계값 구조(아래 G2)와 라벨 잡음이다.

| char-CNN `_bal` (기준) | 0.980 | 0.9853 | 0.295 | 0.9794 | 0.383 | 0.738 |
| BiLSTM `_bal` | 7.277 | 0.9592 | 0.255 | 0.9540 | 0.305 | 2.585 |
| TF-IDF+LogReg | 0.290 | 0.9382 | 0.215 | 0.9343 | 0.228 | 0.429 |

(t1 = 0.363ms, 이 실행. §8.16 의 0.292ms 와 다른 것은 실행 간 흔들림 — 같은 실행 값끼리만 비교.)

- **판정(§8.14 기준 그대로)**: BiLSTM → 같은 지연 이하의 char-CNN 점보다 F1 이 높은 점이 없다 → **기각**. TF-IDF → 기대 지연 0.397ms 점(예산 0.13, F1 0.9194)이 지연 0.394ms 의 char-CNN 점(예산 0.04, F1 0.9011)보다 +1.84pp, 부트스트랩 95% CI [+1.44, +2.23]pp → **기준 충족, "대안 2차로 병기"**.
- ⚠️ **기준이 잡은 것은 저정확도 구간이다.** TF-IDF 곡선은 2차 단독 F1 0.938 에서 막힌다. 운영점 목표(char-CNN val F1 − 0.5pp ≈ 0.98)에는 원리상 닿지 못하므로, 논문의 권장 구성(운영점 구간)은 **char-CNN 2차 유지**다. TF-IDF 가 이기는 구간은 F1 0.94 이하(기대 지연 약 0.46ms 이하)뿐이다. 이 점(F1 최대 이득 점 하나에만 CI 를 낸 것)은 곡선 전체에서 고른 사후 최대값이라는 점도 함께 적는다.
- **탐색 관찰(판정 아님, 중요)**: **TF-IDF 단독**(0.290ms, F1 0.938)이 1차 RGB CNN 단독(0.363ms, F1 0.867)보다 빠르고 정확하며, F1 0.938 에 닿는 가장 싼 캐스케이드(char-CNN 2차, 예산 0.11, 0.460ms)보다도 1.6배 빠르다. TF-IDF 지연은 변환을 포함하고 torch 지연은 이미지 변환(노트북 실측 0.51ms)을 빼고 쟀으므로, 측정 범위 차이는 TF-IDF 에 **불리한** 쪽이다. 즉 **F1 0.94 이하 구간에서는 RGB CNN 1차의 캐스케이드가 필요 없다** — 캐스케이드의 존재 이유는 F1 > 0.94 구간뿐이다.
  - 따라서 "TF-IDF 를 1차로 쓰는 캐스케이드"가 현 권장 구성(RGB CNN 1차)보다 나을 가능성이 열려 있다. 이번 사전 등록 범위 밖이라 측정하지 않았다(후속 실험 후보, 측정 전에 기준을 먼저 고정할 것).
- BiLSTM 은 2차 단독 F1 이 char-CNN 보다 낮고(0.959) 7.4배 느려 모든 구간에서 지배당한다.

### 8.20 교수 기준의 "개선"과 정확도–속도 경계 비교 (2026-10-07, 탐색 — 판정 아님)

**교수 기준(사용자 전달, 2026-10-07).** "개선"이라는 말은 가장 수치가 좋은 유사 연구와 비교해 **정확도(Y)–속도(X) 그래프에서 조금이라도 위**에 있으면 쓸 수 있다.
이 기준은 곡선 **전체**를 본다. 사전 등록 판정(§8.5 과잉 넘김 배율)은 "char-CNN 단독 F1 에 닿는 넘김" 즉 곡선 **꼬리 한 점**만 봤다 — 두 기준이 G2 에 대해 다른 답을 낸다.

⚠️ **아래는 G2 를 찾아낸 CV 데이터로 기준을 바꿔 다시 본 것이라 탐색이다.** "개선"으로 쓰려면 이 기준을 판정 규칙으로 먼저 고정하고 새 seed 재학습 CV 로 확인해야 한다(HARKing 방지).

**재현**: `python src/eval/gate_frontier.py`(CPU 수십 초, G1 과 같은 두 cvprobs). 산출 `experiments/results/gate_frontier_srbh_4class.json`, 그림 `docs/figures/cascade/gate_frontier_b0_g2_srbh_4class.png`.
X = S = t2/(t1 + E_π·t2)(π=3.3%, T2 실측 ms), Y = fold-test Macro-F1. 게이트 경로가 예산 순서로 단조롭지 않으므로(G2 탐욕 경로) 각 속도에서 "그 속도 이상의 최고 F1" 경계로 비교한다. r_N 은 fold-test 정상 전체(96% 스캐너)와 실사용자 층만(G4 보정) 두 판본.

- **공정 지연 기준으로 2차 단독보다 빠른 구성이 처음 나왔다**: TF-IDF → char-CNN 은 검증 분포에서 1.24배다(F1 0.9834, 2차 단독 0.9884 대비 −0.50%p). 1차가 2차보다 빠르고(0.295 < 0.393ms) 넘김이 5.3% 뿐이기 때문이다.
- ⚠️ **실사용자 분포에서는 0.86배로 다시 1배 아래다.** 정상 넘김이 5.2% → 43.4% 로 뛴다(RGB CNN 1차의 44.6% → 69.4% 와 같은 현상, §8.15). "TF-IDF 1차 캐스케이드가 빠르다"는 검증 분포(스캐너 96%) 한정이다.
- ⚠️ **상한이 1.33배다.** 넘김을 0 으로 만들어도 2차 단독의 1.33배를 못 넘는다 — 2차(char-CNN, 0.39ms)가 이미 1차만큼 싸기 때문이다. 캐스케이드가 큰 배수를 내려면 2차가 훨씬 비싸야 한다(Tasdemir 의 20배는 2차가 BERT 2.04ms · 1차가 0.0003ms).
- 해싱(가)은 1차 단독 정확도가 RGB CNN 보다 높지만(0.9078) 호출당 1.95ms 로 더 느려 탈락이다. sklearn `HashingVectorizer` 의 호출당 고정 비용이 크다(2^18 차원 희소 행렬 생성).
- **Q 통계량**(1차·2차가 같은 행에서 틀리는 정도, 1 에 가까울수록 같이 틀림): RGB CNN 0.954 < 해싱 0.993 < TF-IDF 0.996. **표현 이질성은 실제로 오류를 덜 겹치게 한다** — 다만 그 차이가 속도로도 정확도로도 이어지지 않았다. 운영점의 캐스케이드 F1 은 세 1차가 0.9830~0.9839 로 같다.
- 탐색(사전 규칙 밖): 클래스별 임계값(G2)을 TF-IDF 1차에 얹으면 검증 분포 1.318배(E_π 0.7%, F1 0.9868) · 실사용자 **1.306배**(E_π 1.5%, 이득 +52%, p 0.001)다. 실사용자 분포의 과잉 넘김을 클래스별 임계값이 거의 지운다. G2 를 이 1차에 적용하는 것은 사전에 정하지 않았으므로 관찰로만 적고, 확인은 새 seed 가 필요하다.
- ⚠️ 측정의 한계: (1) sklearn 파이프라인을 호출 그대로 쟀다(`pipeline.predict_proba([text])`) — 이미지 변환을 파이썬 그대로 잰 것과 같은 원칙이지만, 두 쪽 모두 구현 최적화 여지가 다르다. (2) 1차 지연(0.295ms)과 2차 지연(0.393ms, E1)은 다른 실행의 값이고 실행 간 4~6% 표류가 있다 — 상한 1.33 이 1 아래로 뒤집힐 크기는 아니다. (3) 선형 1차의 seed 반복은 하지 않았다(로지스틱 회귀는 결정론에 가깝지만 fold 배정은 seed 42 하나).

### 8.27 T5 결과 — 템플릿 묶음 교차검증: 두 모델 모두 점수가 내려가지 않았다 (2026-10-11, 판정)

**판정 규칙**: `docs/paper_revision/03_prereg_v2.md` §T5(커밋 `2a456d7`). 숫자·긴 토큰을 가린 요청 템플릿을 묶음으로 삼아 같은 템플릿이 학습과 fold-test 에 함께 들어가지 않게 나눈 5-fold(seed 42)에서, RGB CNN 이나 char-CNN 의 Macro-F1 이 일반 분할(seed 42)보다 **2%p 이상** 내려가면 "템플릿 중복이 점수를 부풀린다"로 쓰고 본문 수치를 묶음 기준으로 바꾼다. 아니면 "템플릿 중복에 견고". 묶음 분할 위의 B0·G2 경계 비교는 탐색.

**재현**: `python src/eval/cross_validate.py --track srbh_4class --model {cnn --channels rgb|charcnn} --exclude-test --save-probs --group-template`(tag `_gtpl`, `StratifiedGroupKFold`) → `python src/eval/gate_confirm.py --seed 42 --group-template`(→ `gate_confirm_srbh_4class_gtpl.json`).

**판정: "템플릿 중복에 견고"** — 두 모델 모두 하락 폭이 2%p 에 한참 못 미친다(RGB CNN −0.06%p, char-CNN 은 오히려 +0.10%p). 본문 수치는 일반 분할 그대로 둔다.

- **분리는 실제로 됐다**(cvprobs 의 fold 인덱스와 `cross_validate.template_groups` 로 직접 셈, 2026-10-11): 일반 분할에서는 fold-test 행의 **66.5%** 가 같은 fold 의 나머지(학습+검증)에 같은 템플릿을 갖고 있었고(클래스별 SQLInjection 70.7% · CodeInjection 63.0% · Normal 59.7% · CommandInjection 14.7%), 묶음 분할에서는 **0%** 다. 점수가 안 내려간 것은 분리가 안 돼서가 아니다.
- 읽는 법: 템플릿이 겹치지 않아도 모델이 푸는 문제의 난이도는 같았다 — 두 모델이 외우는 것이 "본 적 있는 요청 틀"이 아니라는 뜻이다. 다만 RGB CNN 의 fold 간 표준편차는 0.0140 → 0.0254 로 커졌다(묶음 크기가 고르지 않아 fold-test 크기가 44,002~46,554 로 흔들리고, fold 5 는 0.8655 까지 내려갔다). 평균은 같지만 분할 운에 더 민감해진다.
- 템플릿 수의 차이: 이 풀(train+val 226,048행)의 템플릿은 **96,037개**(그중 70,490개가 1행짜리로 전체 행의 31.2%), `docs/paper_revision/01_why_results_low.md` 에 적힌 108,260개는 test 까지 넣은 전체 265,939행 기준이다. 정의는 같고 풀만 다르다.
- ⚠️ 한계: 템플릿 키는 숫자와 긴 토큰만 가린다. 같은 공격 도구가 만든 "틀은 다르지만 비슷한" 요청은 여전히 양쪽에 들어간다 — 이 결과는 "정확히 같은 틀"의 누수가 없다는 것까지만 말한다.

**묶음 분할 위의 B0 · G2 경계(탐색 — 판정 아님)**. 모델을 묶음 분할에서 새로 학습했지만 seed 42 이고 G2 를 찾아낸 행을 그대로 쓰므로 확인 실험이 아니다.

|---|---:|---:|---:|---:|---:|
| val 혼합: G2 − B0 (%p, 위인 fold) | +1.05 (4/5) | +1.67 (5/5) | +2.29 (5/5) | +2.66 (5/5) | 0.21 |
| 실사용자: G2 − B0 (%p, 위인 fold) | +1.95 (5/5) | +2.68 (5/5) | +3.25 (5/5) | +3.53 (5/5) | 0.16 |

- 검증에서 고른 운영점: 채움 기준 B0 1.362배 → G2 1.897배(**+39.3%**, 보정 p 0.047, F1 손실 0.03%p, E_π 46.9% → 21.7%), 실사용자 1.044배 → 1.441배(+38.1%, p 0.057). 공정 지연(E1) 기준은 0.264배 → 0.282배.

**논문의 주장이 어떻게 바뀌는가**

1. **속도**: "캐스케이드가 2차 단독보다 빠르다"는 CPU·배치 1 에서 성립하지 않는다(E1). 1차를 고쳐도(E2 0.28배, 가장 빠른 이미지 1차 0.47배) 마찬가지다 — 이미지 변환(0.41ms)이 2차 전체(0.39ms)보다 길다. 기존 1.2~1.7배는 "채움 기준"으로만 병기한다.
2. **표현 이질성**: 속도에는 필요하지 않고(E3), 오류를 덜 겹치게는 하지만(Q 0.954 vs 0.996) 운영점 정확도는 같다. 제목의 "표현 이질적"은 **검증 대상**이었고 답은 "이득의 근거가 아니다"다. RQ1 의 음성 결과와 같은 방식으로 **그대로 보고**한다(문구를 조용히 바꾸지 않는다).
3. **넘김 판단**: 클래스별 τ 는 네 seed(발견 1 + 확인 3) 모두 경계가 위지만 유의하지 않고, 운영점 이득은 seed 에 따라 16~44% 다. "개선"이 아니라 "일관된 방향, 미확인 크기"로 쓴다. TF-IDF 1차 위에서 실사용자 넘김을 42% → 1.5% 로 지우는 관찰은 다음 확인 실험의 후보다.
4. **견고성**: 점수는 템플릿 중복에 견고하고(T5), 1차 학습 방식 결정은 CV 에서도 선다(T11). seed 42 는 RGB CNN 에 불리한 seed 였다(T10).
5. **교수 기준의 "개선"**: 같은 조건 비교에서 제안 구성은 위가 아니다. 논문의 기여 문장은 "공정 지연으로 재면 표현 이질적 캐스케이드의 속도 이득이 사라지고 그 원인이 1차 전처리 비용임을 보였다 + 넘김 판단의 한계를 여섯 가지 게이트로 분해했다"로 옮긴다.

**다음 후보(우선순위순, 전부 새 판정 기준을 먼저 적은 뒤)**: ① TF-IDF 1차 + 클래스별 τ 의 새 seed 확인(실사용자 1.31배가 서는지) ② 이미지 변환의 벡터화 구현(0.41ms 바닥을 낮출 수 있는지 — ONNX 는 미실시) ③ 2인 라벨 감사 ④ `cnn_1d` 의 seed 반복.

### 8.30 딥러닝 한정 후속 후보 세 가지 등록 — DL-A · DL-B · DL-C (2026-10-11, 등록만 · 미측정)

⚠️ 이 절은 **후보 등록**이다. 새 측정은 없고, 아래 수치는 전부 앞 절에서 이미 잰 값이거나 논문 보고값이다. 판정 기준은 측정 전에 `docs/paper_revision/` 에 따로 적는다(§2 공통 원칙).

**등록 경위 — 왜 이 셋인가**

1. **범위를 좁혔다(2026-10-11 사용자 방향)**: 제안 구성은 고전 ML(TF-IDF·XGBoost 등)을 빼고 **딥러닝 모델만으로** 잡고 싶고, **RGB CNN 을 꼭 쓰지 않아도 된다**. 계기는 §8.26 — 같은 조건에서 TF-IDF 선형 1차 구조가 제안 구성을 지배했다. ⚠️ 아직 마스터 설계 문서·제목에 반영한 확정 결정은 아니다(교수 확인 전).
2. **딥러닝만 남긴 비교 그림을 다시 그렸다**(§8.26 의 `--dl-only`): 같은 데이터·같은 CPU 에서 오른쪽 위 꼭짓점은 **char-CNN 단독**(0.9884 · 0.393ms)이고, 딥러닝 1차 캐스케이드 넷은 0.27~0.47배로 모두 1배 왼쪽이었다. 즉 범위를 좁혀도 제안 구성은 위가 아니다.
3. **왜 2차 단독이 더 빠른지를 식으로 내렸다**: 캐스케이드 비용 = t1 + E·t2, 배수 S = t2 / (t1 + E·t2), 상한(E→0) = t2/t1. RGB CNN 1차는 t1 1.311ms > t2 0.393ms 라 넘김을 0 으로 만들어도 0.30배다(§8.21·§8.25). → **조건 ㉠: 1차가 2차보다 충분히 싸야 한다.**
4. **가장 싸고 정확한 딥러닝 모델이 이미 char-CNN 이다**: 2차 후보로 잰 BiLSTM 은 더 느리고 덜 정확했고(§8.18, test 0.9592 vs 0.9853), RGB 계열 1차는 전부 char-CNN 보다 비싸다(§8.25). → **조건 ㉡: char-CNN 보다 싼 딥러닝 1차를 따로 두기는 어렵다.**
5. **㉠·㉡을 동시에 푸는 방법은 구조상 셋뿐이다**: char-CNN **뒤에** 더 무거운 모델을 둔다(DL-A) · char-CNN **앞에** 더 가벼운 모델을 둔다(DL-B) · 모델을 **나누지 않고** 중간에서 끝낸다(DL-C). 셋 다 후보로 등록한다(사용자 지시).

- 넘김 = 표준 MaxProb(B0)와 클래스별 τ(G2)를 나란히, 지표 = E_π(π 3.3%)와 실사용자 r_N 병기(§8.15).

- 비교 대상 = **char-CNN 단독**(딥러닝 경계)이 1차 기준. TF-IDF 선형 1차 구조는 제안 구성에서는 빼되 **비교 기준으로는 싣는다** — 지우면 비교 대상 선택 편향이다(§8.26 경고).
- "개선"은 교수 기준(§8.20)대로 곡선이 char-CNN 단독 점의 위·오른쪽을 지날 때만 쓴다.

**권장 순서**: ① DL-B·DL-C 공통 관문(층별 시간 측정 — 학습 불필요, 짧다) ② DL-A 관문(트랜스포머 단독 CV — GPU 필요. `transformers` 는 이 데스크톱에 4.57.3 이 설치돼 있다 — 2026-10-11 `python -c "import transformers"` 로 확인, 다른 기기에서는 재확인) ③ 관문을 통과한 후보만 판정 기준을 적고 본 측정.

### 8.31 DL-B·DL-C 관문 — char-CNN 단계별 지연 (2026-10-25, 판정 기준 `docs/paper_revision/03_prereg_v2.md` §E7, 기준 커밋 4b7843b)

  - seed 43 에서는 **모든 fold 의 운영점이 넘김 0%** — 배포 구성은 사실상 "결합 학습한 k3 분기 + 보조 헤드"이고 k5·k7·본 헤드는 돌지 않는다. 보조 헤드 − 단독 fold 차이 +1.39 · −0.26 · −0.10 · +0.41 · +0.19%p. 본 헤드 단독은 0.9923.
- **E9-3 그림**: `docs/figures/cascade/literature_comparison_dl_only_srbh_4class.png` 에 DL-C(0.109ms 환산, F1 0.9874)와 k3 단독(0.109ms, 0.9748)을 더했다. 기본 그림(고전 ML 포함)은 바이트 단위로 그대로. (a) 패널에서 DL-C 는 딥러닝 보고값(WAMM BiLSTM 0.713ms·0.7711, DistilBERT 14.4ms·0.8547) 보다 빠르고 높게 찍히지만 데이터 정제·클래스·기기가 달라 **"유사 연구 대비 개선"으로 쓰지 않는다**(사전 문서 §E9-3).
- **종합 — 쓸 수 있는 문장**: ✅ "char-CNN 을 커널 3 분기 보조 출력과 함께 학습하면, 그 보조 출력 하나로 char-CNN 단독과 같은 정확도(seed 42 −0.10%p · seed 43 +0.33%p)를 약 3.5~3.6배 빠르게 낸다(CPU·배치 1, 사전 기준 2/2)" / ✅ "같은 크기 모델을 단독 학습하면 이 설정에서 1.36%p 낮다(유의성은 보조 헤드와의 차이 p 0.34 로 미확인, 단독 학습 불안정)" / ❌ "넘김 판단 개선" · ❌ "조기 종료 구조가 이득의 원인"(seed 43 은 넘김 0%) · ❌ "유사 연구 대비 개선".
  - 논문 축(RQ5 ② 넘김 판단)과의 관계: DL-C 의 이득은 넘김이 아니라 **2차 모델 압축(결합 학습)**이다 — 넘김 축의 결과로 쓰면 안 되고, ① 속도·정확도 교환 축에서 "캐스케이드 없이도 얻는 기준선"으로 서술하는 것이 정직하다. 마스터 문서 반영은 교수 확인 후.
- 후속 후보(미측정·미등록): k3 단독의 학습 안정화(lr 3e-4 또는 인내 10) 대조 — 이것으로 "결합 학습 = 최적화 안정성"인지 가른다. 사전 기준 작성 후.

### 8.34 DL-A — 트랜스포머 관문 · 같은 조건 유사 연구(WAMM DistilBERT) 재구현 · char-CNN → DistilBERT (2026-10-25, 판정 기준 `docs/paper_revision/03_prereg_v2.md` §E10, 기준 커밋 00c52ce · 모델 3f5aeed · 판정 코드 559c8df)

- **E10-3 char-CNN → DistilBERT**(1차 char-CNN, 2차 DistilBERT, 운영점은 fold 마다 val 에서): 실사용자 B0 **평균 비용 기준 12.3배**(fold 46.9 · 47.7 · 80.2 · **2.95** · 80.2 의 조화평균 = fold E_π 평균으로 다시 낸 배수) · F1 **0.9911**(R 대비 −0.03%p) · r_N 7.1% · r_A 0.7% → 세 조건 충족, **판정: "같은 fold·같은 CPU 로 재구현한 DistilBERT 단독보다 위"(seed 42)**. 검증 분포 판본 47.5배 · G2 병기 실사용자 51.1배.
  - ⚠️ **2026-10-27 정정**: 처음 기록한 51.6배(검증 분포 63.4배 · G2 57.5배)는 fold 배수의 **산술평균**이다. 산술평균은 넘김이 많은 fold 4 의 비용을 거의 무시해 배포 비용을 과대평가한다 → 평균 비용 기준(합산)으로 바꿔 적는다. 12.3배 ≥ 1.2 라 **판정은 그대로**다. 이후 판정(§E11)은 합산 배수로 사전 고정했다. 산술평균은 병기만 한다.
  - char-CNN 단독 대비(기술): F1 +0.28%p(fold +0.83 · +0.01 · 0 · +0.52 · +0.01, 보정 p 0.34 — **유의하지 않음**) · 지연 배율 평균 비용 기준 **0.154(= char-CNN 단독보다 6.5배 느림**, 실사용자; 산술평균으로는 0.64 = 1.56배였다 — 같은 이유로 정정). "char-CNN 단독보다 정확"이라 쓰지 않는다.

### 8.35 DL-A 확인 seed 43 — char-CNN → DistilBERT 는 seed 43 에서 재구현 DistilBERT 단독보다 위가 아니었다 (2026-10-27, 판정 기준 `docs/paper_revision/03_prereg_v2.md` §E11, 기준 커밋 f37fd70 · 판정 코드 42c7596)

- 명령: `python -u src/eval/cross_validate.py --model distilbert --track srbh_4class --exclude-test --save-probs --epochs 3 --batch-size 16 --lr 2e-5 --seed 43`(GPU, 에폭 약 410초 · fold 당 약 21분, 로그 `experiments/logs/e11_distilbert_s43.log`) → `python src/eval/dl_a.py --analyze --seed 43` → `dl_a_srbh_4class_s43.json`. 1차는 E9-2 의 `cvprobs_srbh_4class_charcnn_raw_sealed_s43.npz`, 지연은 E10 실행 값 재사용(t2 0.563 · t_R 45.15ms). 정렬 검증 통과.
