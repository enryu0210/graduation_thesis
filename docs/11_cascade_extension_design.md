## 0. 왜 이 Phase 인가 — 선행연구 대조가 만든 결론

`docs/thetics/` 8편을 전문 대조한 결과 두 가지가 드러났다.

**① 정확도 개선폭의 기준선이 낮다.** *Scientific Reports*(Tadhani et al. 2024)가 헤드라인으로 삼은
개선은 CNN 베이스라인 대비 **+0.34pp**(99.5 → 99.84)이고, *Appl. Sci.*(Eroğlu Demirkan 2025)는
선행 대비 **+0.11~1.27pp** 로 "surpassing existing benchmarks" 라고 쓴다. 우리 gray→RGB
**+2.69pp(5-fold CV)** 는 이보다 한 자릿수 크고, **8편 중 유의성 검정을 한 탐지 논문은 0편**이다.
→ 수치 자체는 부족하지 않다. 다만 **단일 RGB CNN 을 헤드라인에 올리면**(csicnorm MCC 0.9725)
선행보다 낮아 보이므로, 보고 단위는 반드시 **캐스케이드**(MCC 0.9941)여야 한다.

**② 8편 중 회피/적대적 실험을 한 논문이 0편이다.** 즉 우리의 RQ2·RQ3 축은 경쟁자가 없다.
그런데 그 축에서 우리가 가진 것은 아직 **"제안 모델도 흔들린다"는 음성 결과**뿐이다.

**→ 이 Phase 의 목적**: 캐스케이드에 **단일 모델이 원리적으로 가질 수 없는 능력**을 붙여,
"싸다"는 것 말고 **제안 모델이어야만 하는 이유**를 만든다.

> 참고 정정 — `docs/thetics/시그니처 기반 필터링과 2D-CNN…`(김지민 외)은 **한국통신학회
> 하계종합학술발표회 2쪽 발표문**이며 KCI 등재지 논문이 아니다. 구조도 다르다(1차 Suricata 룰셋,
> 2차는 **정상만 학습한 Open-set 이상탐지**). 우리 캐스케이드(학습된 CNN 1차 + 확신도 게이트 +
> τ 연속 곡선)와 겹침 위험은 당초 우려보다 작다. 관련연구에서 한 문단으로 구분하면 충분하다.

## 2. 이번 Phase 가 새로 하는 것 — 3안

**공통 원칙**: 세 안 모두 **캐스케이드 구조를 전제**로만 성립하거나, 캐스케이드에서 이득이 커진다.
"단일 모델로도 되는 것"은 제안 모델의 존재 이유가 되지 못하므로 넣지 않는다.

| ID | 이름 | 노리는 축 | 캐스케이드 고유성 | 새 학습 |
|---|---|---|---|---|
| **M1** | 표현 간 불일치 → **회피 시도 탐지** | 못 잡던 것 | ⭐ 두 표현을 이미 계산하므로 **추가 비용 0**. 단일 모델은 원리적으로 불가 | **없음** |
| **M2** | **인코딩 불변 채널 인코더** | 못 잡던 것 | 1차 입력을 바꾸는 것이라 게이트 품질(F6)에도 영향 | 1~2셀 |
| **M4** | **다단 조기종료**로 1차 비용 절감 | 속도 | 캐스케이드 비용식의 `C_cnn` 항을 직접 낮춤 | 1셀 |

### 2.1 보류한 안 — M3(CAM 크롭 인계)

1차 CNN 의 Grad-CAM 상위 영역을 **바이트 오프셋으로 역변환**해(픽셀 `(r,c)` ↔ 오프셋 `r*48+c`,
docs/08 §2 의 전단사 성질) 2차 char-CNN 입력을 잘라 주는 안. 속도·정확도 양쪽 가능성이 있고
신규성도 높으나, **CAM 부정확 시 결정적 바이트가 잘려 2차가 망가지는 실패 모드**가 있어
구현·검증 비용이 위 3안보다 크다. → **Phase 13 후보로 보류**(§8 열린 결정).

## 3. M1 — 표현 간 불일치를 '회피 시도' 탐지 신호로 ⭐

### 3.1 착안 근거 (전부 기존 실측)

| 상황 | 1차(RGB CNN)와 2차(char-CNN)의 관계 |
|---|---|
| clean | 탐지집합 **완전 일치**(F4). 즉 두 표현이 거의 안 싸운다 |
| 변형 k=5 | any-misclass **char-CNN 0.224 vs RGB CNN 0.598**(F9 표) — 격렬하게 갈린다 |

지금까지 이 격차는 "캐스케이드의 약점"으로만 읽혔다. 뒤집으면 **잡음(clean)이 거의 없고
신호(변형)가 큰 탐지기**다.

### 3.2 방법

캐스케이드에 4-class 판정과 **별개의 세 번째 출력** `tampering_score` 를 단다.

```
tampering_score = D( p_stage1(·|x) , p_stage2(·|x) )
```

- `D` 후보: ① top-1 불일치(이진) ② JS-divergence ③ 1차 확신도와 2차 확신도의 차
  → 세 가지를 ablation 하고 **clean val 에서 임계값 확정 → test 1회 적용**(docs/09 §3.1 원칙 계승).
- **⚠️ 에스컬레이션된 샘플에만 정의된다.** 1차에서 확정된 샘플은 2차 예측이 없다.
  → 두 가지 운영 모드를 **분리 보고**한다:
  - **모드 A(비용 불변)**: 에스컬레이션 부분집합에서만 tampering 판정. 추가 비용 **정확히 0**.
  - **모드 B(전량)**: 전체에 2차를 돌려 상한 측정. 비용은 융합형과 같아지므로 **상한 참고용**.
  - 모드 A 의 커버리지(전체 대비 판정 가능 비율)를 반드시 함께 보고 — 이게 낮으면 실용성이 없다.

### 3.3 왜 새로운가

기존 웹공격 탐지 문헌(선행 8편 포함)은 전부 *"이 페이로드가 공격인가"* 만 묻는다.
이건 *"이 요청이 탐지 회피를 시도했는가"* 를 묻는다. 회피 시도는 그 자체로 적대적 의도의
강한 증거이며, WAF 운영에서 차단·격리·포렌식 우선순위 판단에 직접 쓰인다.
**두 표현을 동시에 유지하는 구조에서만 공짜로 얻어진다** — 이것이 제안 모델이 캐스케이드여야
하는 두 번째 이유가 된다(첫 번째는 비용, F5).

### 3.4 G3 와 함께 해결

같은 실행에서 **변형 테스트셋 상보성 분석**(`detection_analysis.py`)을 돌린다.
clean 에서 순증이 0 이었던 표(F4)가 변형 하에서 어떻게 바뀌는지가 "몇 건을 더 맞추는가"의
직접 근거다. 방어 캐스케이드(any-misclass 0.0287) vs char-CNN base(0.224) 격차는 공격
21,907건 기준 **약 4,300건 규모**로 예상된다. ⚠️ 단 이는 미탐이 아니라 **오귀속(misattribution)**
이므로, docs/10 §1.2 의 운영 비용 근거(대응 playbook·차단 규칙이 유형으로 갈림)를 반드시
같은 문단에 쓴다. **"더 많이 탐지한다"로 과장 금지.**

## 4. M2 — 인코딩 불변 채널 인코더

### 4.1 착안 근거

F9(적대적 증강이 미지 변형에 실패)의 원인은 F11 이다 — 동요를 만든 3종 중 2종이 인코딩
계열이고, S-A 에서 그것이 held-out 이라 **학습이 배울 것 자체가 없었다.**
학습으로 못 얻는 불변성은 **구조로 넣는다.**

### 4.2 방법

`channel_encoders.py` 레지스트리에 인코더를 추가한다(레지스트리라 코드 구조 변경 없음).

- `normalized_char_class` (약어 `nc`): `%XX`·`&#NN`·`&name;` 를 해독한 **뒤의** 문자 클래스를 채널값으로.
- 기본 배치안: **R=raw_byte / G=normalized_char_class / B=local_entropy** (`_rgb-rb-nc-le`)

**⚠️ R 채널(raw)은 그대로 둔다.** 이것이 정규화 방어(docs/10 §3 B안)와의 결정적 차이다.
B안은 디코딩한 결과만 보므로 원본 정보를 잃고, 그래서 *"정상 트래픽도 디코딩되어 FPR 이
오를 수 있다"* 는 리스크가 있었다(docs/10 §10). 채널로 넣으면 **원본 뷰와 정규화 뷰를 동시에**
보므로 그 트레이드오프가 사라지고, *"인코딩을 썼다는 사실"* 자체도 신호로 남는다.

### 4.3 왜 새로운가

적대적 증강(학습형)과 입력 정규화(전처리형) 사이의 **제3의 위치** — 불변성을 이미지화
표현 자체에 넣는다. 규칙 기반이므로 **학습에서 본 적 없는 인코딩 변종에도 원리적으로
일반화**된다. F9 가 실패한 지점을 정면으로 겨냥한다.

## 5. M4 — 다단 조기종료로 1차 비용 자체를 낮추기

### 5.1 착안 근거 — 게이트 최적화로는 못 넘는 천장이 있다

캐스케이드 비용식(docs/09 §2, 실측값 대입):

```
C(r) = C_cnn + r · C_charcnn = 0.0066 + r × 0.0561  [ms/sample]
```

지금까지의 모든 논의는 **`r` 만** 건드렸다. `C_cnn` 은 상수로 뒀다. 그런데:

| 라우팅 | r | C | char-CNN 대비 |
|---|---|---|---|
| 현행 대표 운영점(budget 10%) | 7.99% | 0.0111 | 5.07배 |
| 현행 match-teacher | 27.73% | 0.0222 | 2.52배 |
| **oracle 상한**(F6) | 1.87% | 0.0077 | **7.29배** ← 게이트를 완벽히 고쳐도 여기가 끝 |

**7.29배가 천장**이고, 그 원인은 `C_cnn = 0.0066` 이 바닥이기 때문이다.

### 5.2 방법

1차 RGB CNN(Conv 32→64→128 + GAP) 내부에 **조기 종료 헤드**를 단다. 대부분의 트래픽이
첫 블록에서 확정되면 평균 1차 비용이 내려간다. 캐스케이드가 사실상 **3~4단**이 된다.

`C_cnn` 이 절반(0.0033)이 된다고 가정하면:

| 운영점 | 현행 | M4 적용 후(가정) |
|---|---|---|
| budget 10% (r=7.99%) | 5.07배 | **7.21배** |
| match-teacher (r=27.73%) | 2.52배 | 2.97배 |
| oracle (r=1.87%) | 7.29배 | **12.9배** |

**이득은 저에스컬레이션 운영점일수록 크다**(2차 비용이 작아 1차가 지배적이므로).
→ **게이트 개선(F6)과 M4 는 상보적**이며 곱해진다. 논문에서는 두 축을 분리해 보고한다.

### 5.3 왜 새로운가

조기 종료 자체는 알려진 기법이지만, **비용식으로 "게이트 최적화로 도달 불가능한 천장"을
먼저 정량화하고 그 천장을 무너뜨리는** 구성은 캐스케이드 문헌에서 드물다. 그리고 τ 스펙트럼과
직교한다.

### 5.4 구현 시 반드시 함께 갱신할 곳 (CLAUDE.md 규칙)

- [ ] `src/models/cnn.py` — 조기종료 헤드(블록별 보조 분류기)
- [ ] **`IMAGE_MODELS` 를 2곳 동시 갱신** — `train.py` · `cross_validate.py`
- [ ] 손실 = 최종 헤드 + 보조 헤드 가중합 → 가중치를 tag 축에 넣을지 결정(§6)
- [ ] `cascade.py` — 1차 비용을 **실측 평균**으로 계산(고정 상수 사용 금지. 조기종료는 샘플마다 비용이 다름)

## 6. ⚠️ 산출물 tag 규약 — 축을 **쓸 수 있게 되기 전에** 넣는다

이 프로젝트는 tag 축 누락으로 산출물이 서로 덮어쓰는 사고를 **세 번** 겪었다
(커밋 5eede2f RGB 조합 / docs/09 §9.7 τ 축 / docs/10 §5.1 캐스케이드 채널 축).
특히 세 번째는 *"막아둔 조합이 tag 버그를 가리고 있다가 차단을 푸는 순간 덮어썼다"* 였다.

**→ 이번에는 구현 착수 시점에 tag 축을 먼저 넣는다.** 실측 전이라도 마찬가지다.

| 방안 | 새 tag 축 | 규칙 |
|---|---|---|
| M1 | 없음(모델 불변) | 산출물은 `tamper_{cascade_tag}.json` 로 분리. `D` 종류·모드(A/B)를 JSON 에 기록 |
| M2 | 채널 접미사에 자동 반영 | `_rgb-rb-nc-le` — 기존 `_channel_suffix` 경로 그대로. **약어 2곳 동시 갱신 필수** |
| M4 | `_ee`(+ 보조손실 가중치·종료 임계값) | 기본값이면 생략해 **기존 파일명과 호환**(`_lr` 관습 계승) |

규칙 추가는 `src/models/tagging.py` **한 곳**에서만 한다(사본 금지 — 그래서 만든 모듈이다).

## 7. 판정 기준 — 실측 **전에** 고정한다 (HARKing 방지)

docs/10 §6 의 관행을 계승한다. **결과를 보고 조정하지 않는다.**

| # | 가설 | 판정 기준 |
|---|---|---|
| **H5-1** | 표현 불일치가 회피 시도를 판별한다 | 변형 여부 이진 판별 **ROC-AUC ≥ 0.90 = 효과 있음**, 0.75~0.90 = 보조 지표로만 보고, < 0.75 = **기각** |
| **H5-2** | 그 판별이 실용적이다 | clean Normal 오탐 **≤ 1%** 이고, 모드 A 커버리지 **≥ 30%** |
| **H6-1** ⭐ | 인코딩 불변 채널이 **미지 변형**에 일반화된다 | S-A 감소폭 ≥ S-0 감소폭의 **50%**(H3-3 기준 계승). 달성 시 **F9 를 처음으로 뒤집음** |
| **H6-2** | 그 대가가 수용 가능하다 | clean MCC 하락 **≤ 1pp**, FPR 상승 **≤ 0.5pp**(H3-2 계승) |
| **H7-1** | 조기종료가 1차 비용을 낮춘다 | 같은 test MCC(**±0.11pp** 이내) 유지하에 평균 1차 비용 **≥ 30% 감소** |
| **H7-2** | 그것이 캐스케이드 속도로 이어진다 | 대표 운영점(budget 10%) speedup **5.07배 → ≥ 6.5배** |

**단일 split 규칙**: 실행 간 변동은 ±0.11pp(CLAUDE.md). 위 기준은 그보다 크므로 단일 split 로
보고 가능하나, **H6-1 이 40~50% 경계에 걸리면 5-fold CV 로 재판정**한다.

## 8. 실행 순서 (구현 후 재현) — 머신별 구분

```bash
# ─────────── 노트북(CPU) 에서 가능 ───────────
python src/data/preprocess.py                    # 인자 없이 전체(노트 유지)
python src/imaging/build_image_dataset.py --track payload_4class_csicnorm --channels rgb
python -m pytest tests/ -q                       # 커밋 전 필수(~3초)
# M1 은 기존 예측 npz 만 있으면 계산 가능 → CPU 로 선행 가능
# M2 인코더·M4 헤드는 --smoke 로 코드 경로만 점검(추적 그림 저장 생략)

# ─────────── 데스크톱(GPU) 실측 ───────────
# 0순위: 기존 구멍부터 (G1 → G2)
python src/attacks/run_evasion.py --model charcnn --track payload_4class_csicnorm \
    --defense advtrain --mutation-split S0 --aug-ratio 0.25    # ×4셀 (G1)
# (G2) 정규화 방어 2셀 — docs/10 §9 명령 그대로

# M1: 새 학습 없음 — 캐스케이드 예측에서 불일치 산출 + 변형 상보성(G3)
# M2: npz 재빌드 → 1차 CNN 재학습 → 방어 arm 회피 재평가
# M4: 조기종료 학습 1셀 → cascade.py 로 비용 곡선 재측정
```

⚠️ GPU 는 1대뿐 → **순차 실행**. 백그라운드가 "killed" 로 보여도 파이썬 자식은 살아 있을 수
있으므로 재실행 전 `Get-CimInstance Win32_Process -Filter "Name='python.exe'"` 로 확인.

## 9. 리스크 / 열린 결정

- [ ] **M1 의 커버리지 문제**: 모드 A 는 에스컬레이션된 샘플에만 정의된다. 대표 운영점의
      esc 가 7.99% 라면 92% 는 판정 불가다. → 커버리지-성능 트레이드오프를 τ 스윕으로 그리고,
      "τ 를 올리면 tampering 커버리지가 오른다"는 **새로운 τ 해석 축**으로 서술할 여지가 있다.
- [ ] **M1 이 방어 학습본에서 약해질 위험**: 방어로 1·2차가 둘 다 안정되면 불일치 신호도 줄어든다.
      → base 구성과 방어 구성 **양쪽에서** 측정하고, 줄어들면 그 자체를 보고한다.
- [ ] **M2 가 사실상 정규화 방어(B안)와 같아질 위험**: 채널 하나만 바꾼 것이 B안의 효과를
      대부분 흡수하면 "새 방법"이라 주장하기 어렵다. → **G2(B안)를 먼저 실측**해 비교 기준을
      확보한 뒤 M2 를 판정할 것. 순서를 지킨다.
- [ ] **M4 의 정확도 손실**: 조기종료는 보조 헤드가 본 헤드 학습을 방해할 수 있다.
      H7-1 의 MCC 조건(±0.11pp)을 못 지키면 **채택하지 않는다**(docs/08 의 hybrid 처럼
      "시도했으나 미채택"이 정직한 보고).
- [ ] **M3(CAM 크롭 인계) 착수 여부** — Phase 13 후보. §2.1 참조.
- [ ] **G4 적응형 공격은 수행하지 않음** — 한계로 명시(방어 논문의 표준 비판 지점).
- [ ] **G6 RQ4b 처리 방침**(부록 강등 vs host 단위 재실험) 미결정.
- [ ] (운영) 브랜치 정리 — 여전히 `phase1-data-acquisition` 에 전 Phase 누적.

## 10. 요약 — 이 문서가 확정한 것

1. **보고 단위는 캐스케이드**다. 단일 RGB CNN 수치를 헤드라인에 올리면 선행연구 대비 미달로
   보인다(§0). Accuracy 열도 반드시 병기한다 — 선행 8편이 전부 Accuracy 로 보고하므로.
2. 이번 Phase 는 **캐스케이드에만 성립하는 능력** 3안을 추가한다: **M1 표현 불일치 회피 탐지**(새 학습 0),
   **M2 인코딩 불변 채널**(F9 를 겨냥), **M4 다단 조기종료**(속도 천장 돌파).
3. **M3(CAM 크롭)은 보류**, Phase 13 후보.
4. 기존 구멍 **G1(char-CNN 방어 회피 재평가)·G2(정규화 방어)** 를 이번에 함께 갚는다.
   특히 G2 는 **M2 의 비교 기준**이므로 M2 보다 먼저 돌린다.
5. 판정 기준(H5-1/2, H6-1/2, H7-1/2)을 **실측 전에** 고정했다. 사후 조정하지 않는다.
6. tag 축은 **구현 착수 시점에 미리** 넣는다 — 덮어쓰기 사고 3회의 교훈(§6).

**현재 상태: 설계 확정, 구현·실측 전부 미착수.** 다음 착수 시 §8 의 0순위(G1)부터 시작한다.
