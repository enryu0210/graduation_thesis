## 0. 실행 원칙 (모든 작업에 공통 적용)

1. **사전 지정 우선.** 새 실험을 돌리기 전에 판정 기준을 `prereg_v2.md`에 먼저 쓰고 git 커밋한다. 논문 본문에는 그 커밋 해시를 적는다. 영문에서는 "pre-registered" 대신 "pre-specified"를 쓴다.
2. **확증과 탐색을 분리한다.** 기존 데이터로 이미 본 결과를 다시 분석하는 것은 모두 "탐색(exploratory)"으로 표기한다. 이번 수정에서 새로 정하는 기준은 사후(post hoc)임을 명시한다.
3. **시험 집합 사용 규칙.** 모델 선택, 구성 선택, 임계값 결정은 검증 집합 또는 교차검증의 검증 부분에서만 한다. 고정 분할의 시험 집합은 최종 확인에만 쓰고, 어느 표가 시험 집합을 몇 번 썼는지 감사 표(부록)로 남긴다.
4. **모든 숫자에 불확실성을 붙인다.** 평균만 보고하지 않는다. 지연은 반복 측정의 중앙값과 IQR, 속도 배수는 부트스트랩 95% 신뢰구간, 성능은 seed 간 평균±표준편차를 쓴다.
5. **원자료 보존.** 모든 표와 그림은 결과 파일(원자료)에서 자동 생성되게 하고, 논문에 들어가는 숫자와 결과 파일의 대응표를 `results_manifest.md`로 관리한다.
6. **환경 기록.** 실험마다 CPU 모델, 코어·스레드 수, RAM, GPU와 드라이버, 프레임워크와 라이브러리 버전, seed, 날짜, git 커밋 해시를 결과 파일에 함께 저장한다.

## 1. 우선순위 P0: 제출 전 반드시 해결 (결과가 바뀔 수 있는 작업)

### T1. 지연 측정 재설계
- **목적:** 속도 배수의 타당성 확보. 현재는 순전파만 재고, 두 모델의 지연을 따로 재서 식 (4)로 합성하며, 1회 측정에 평균만 보고한다.
- **방법:**
  - 두 가지 범위로 분리해 측정한다. (a) 순전파만, (b) 원시 요청 바이트에서 예측까지의 전 과정(이미지 변환, 문자 종류와 지역 엔트로피 계산, 토큰화 포함).
  - 워밍업 후 조건당 독립 실행 30회 이상, 요청 수 1만 건 이상으로 측정하고 중앙값과 IQR을 기록한다.
  - 캐스케이드는 실제 분기를 거치는 요청 스트림에서 직접 측정한다 (시험 집합 요청을 무작위 순서로 재생하고, π=74.8%, 3.3%, 0.1%에 맞춰 재표본). 직접 측정값과 식 (4) 추정값의 차이를 보고한다.
  - 평균 외에 p50, p95, p99를 보고한다. 캐스케이드는 넘겨진 요청에서 t1+t2이므로 꼬리 지연이 단독 2차보다 나빠지는지 확인한다.
  - CPU 스레드 수 민감도(1, 4, 8)를 확인한다. 배치 1에서 8스레드가 과한지 점검한다.
  - GPU는 매 측정에서 동기화를 보장하고, 전처리 방식과 호스트→장치 전송이 포함되는지 명시한다. GPU 배치 32→128→1024에서 1차의 요청당 지연이 비단조인 이유(현재 0.0081→0.0040→0.0080ms)를 규명하거나 재측정으로 해소한다.
  - 선택: PyTorch 기본 실행과 ONNX Runtime 같은 추론 런타임을 비교해 비율이 런타임에 민감한지 확인한다.
  - 다른 프로세스 부하와 전원 모드를 통제한다 (CPU 고정 등).
- **산출물:** Table 3 전면 교체. 순전파 전용과 end-to-end 두 벌, 신뢰구간, 꼬리 지연.
- **판정 기준(사전 지정):** (i) 헤드라인 S(CPU·배치 1, π=3.3%)를 end-to-end 기준 신뢰구간과 함께 보고한다. (ii) 신뢰구간 상한이 2배 미만이면 "조건부" 판정을 유지한다. (iii) G2와 B0처럼 5% 이내 차이는 신뢰구간이 겹치면 "차이 없음"으로 서술한다.
- **논문 반영:** 4.2절(측정 정의), 5.3절, 5.6절 서술, 한계 절. 요약과 결론의 속도 배수 수치도 갱신한다.

### T2. 이전 데이터셋과의 동일 조건 비교 (t2/t1 문제 해소)
- **목적:** 논의의 "상한 자체가 낮아졌다"가 측정 조건 차이의 산물인지 확인한다.
- **방법:**
  - 이전 데이터셋의 모델로 T1과 같은 8개 조건(장치 2종 × 배치 4종)에서 t1, t2를 재측정한다.
  - 두 데이터셋의 t2/t1을 같은 조건에서 나란히 표로 만든다. (SR-BH의 현재 값: CPU·1은 3.18배, GPU·128은 약 17.5배, GPU·1024는 약 7.9배)
  - 이전 데이터셋의 5.07배(GPU·배치 512, 넘김 8%)를 식 (4)로 재구성한다. t2/t1=13.6이면 식 (4)는 6.5배가 나오므로, 차이의 원인(측정 조건, 오버헤드, 처리량 비의 정의)을 규명한다.
  - 이전 데이터셋의 모델 구조가 SR-BH와 같은지, 입력 길이가 다른지 확인하고 기록한다.
- **산출물:** 두 데이터셋의 같은 조건 t2/t1 표 (신규 Table), 5.07배의 재구성 설명.
- **판정 기준:** 같은 조건에서 두 데이터셋의 t2/t1 차이가 작다면 논의의 "상한이 낮아졌다" 문장을 삭제하고, 속도 이득 차이는 "넘김률 차이" 하나로 설명한다.
- **논문 반영:** 5.3절 마지막 문단, 논의 첫 문단. 이전 데이터셋 수치의 출처(T13)와 함께 정리한다.

### T3. ρ 지표 재정의와 통계 재설계
- **목적:** 게이트 비교의 신뢰도 확보. 엄격한 목표와 n=5 폴드 검정의 문제를 해소한다.
- **방법:**
  - ρ를 허용 오차 ε 버전으로 일반화한다. 목표를 "2차 단독 Macro-F1 − ε"로 두고 ε=0.1, 0.3, 0.5%p에서 각각 e_g, e_o, ρ_ε를 계산한다. 엄격한 목표(ε=0)도 병기한다.
  - e_o의 정의를 둘로 나눠 모두 보고한다. (a) 1차 오답 전체를 넘기는 비율, (b) 목표에 도달하는 최소 오라클 넘김률 (1차 오답 중 2차가 맞히는 것부터 넘김). 식 (3)의 문장과 계산이 일치하게 한다.
  - 넘김 예산 0~50% 구간에서 Macro-F1 곡선을 폴드별과 풀링으로 그리고, 곡선 아래 면적 같은 요약 지표를 추가한다.
  - 통계는 (i) 5-fold 교차검증을 3~5회 반복하고 Nadeau–Bengio 보정 t검정을 쓰거나, (ii) 풀링한 예측에 대해 요청 단위 쌍체 부트스트랩(폴드 층화)을 쓴다. 검정 설계 전에 기존 5개 폴드의 분산으로 검정력 분석을 하고 그 결과를 기록한다.
  - B0, G2, G3-lite, G3-full 모두 같은 기준으로 재분석한다. G3 라우터는 기존 로지스틱 회귀에 더해 GBDT 등 더 강한 모델을 하나 시험한다 (탐색).
  - 기존 사전 기준 (3)의 결과(18.7%, p=0.42 등)는 그대로 보고하고 "검정력 부족"을 명시한다. 새 지표는 "방법론 수정 후 재분석(탐색)"으로 표기한다.
- **산출물:** Table 4, 5, 6 교체 또는 보강. 넘김-성능 곡선 그림 (CV 신뢰대 포함).
- **판정 기준(사전 지정):** G2의 ρ_ε 감소 20% 이상과 보정 p<0.05, 또는 부트스트랩 95% 구간이 0을 포함하지 않으면 "채택". 어느 쪽이든 검정력과 효과 크기를 함께 보고한다.
- **논문 반영:** 3.4절(ρ 정의), 4.2절(판정 기준), 5.4절~5.5절, 초록의 "넘김 판단은 개선하지 못했다" 문장 수위 조정 ("사전 기준을 충족하지 못했다 (검정력 한계 포함)"으로 변경 후, 결과에 따라 확정).

### T4. 배포 현실성: rN과 π의 근거
- **목적:** "배포 조건" 주장의 근거 확보. 현재 rN은 스캐너 트래픽(97.8%)에서 측정되었고 π=3.3%, 0.1%는 출처가 없다.
- **방법:**
  - 실사용자 정상 요청(전체 645개, CV 풀링)에 대한 rN_real을 계산하고 Wilson 신뢰구간을 붙인다. 스캐너 정상과 실사용자 정상을 층별로 비교한다.
  - 외부 정상 트래픽(예: 이전 데이터셋의 CSIC 2010 정상 트래픽)에 SR-BH로 학습한 1차를 적용해 rN을 측정한다 (분포 이동 사례로 서술).
  - π 값의 출처를 정한다 (문헌 인용, 원본 SR-BH의 공격 비율 계산, 또는 "가정"으로 명시). 가능하면 문헌 근거를 인용하고, 근거가 없으면 π를 0.1%~75% 전 구간으로 훑는 민감도 곡선 S(π)를 그린다.
  - 식 (5)의 가정(rN과 rA가 π와 무관)을 본문에 명시한다.
- **산출물:** rN 층별 표, S(π) 곡선 그림 (신규).
- **판정 기준:** rN_real이 rN(스캐너)과 신뢰구간 수준에서 다르면 "배포 배수는 스캐너 기준 추정"이라고 명시하고 헤드라인 문구를 낮춘다.
- **논문 반영:** 3.5절, 4.1절, 5.3절, 한계 절, 초록과 결론의 "배포 조건" 표현.

### T5. 분할 누수와 강건성
- **목적:** 근접 중복에 의한 성능과 넘김률 과대 추정 여부 확인. (Arp 등[1]의 경고 대응)
- **방법:**
  - 요청을 템플릿으로 정규화(숫자, 해시, 긴 토큰 마스킹)한 뒤 시험 집합 요청 중 학습 집합에 같은 템플릿이 있는 비율을 측정한다.
  - 템플릿 그룹 단위로 분할(GroupKFold 방식)해 핵심 결과를 재현한다: RQ1 격차, 운영점 넘김률, 헤드라인 S.
  - 원본에 시간 또는 소스 정보가 있으면 시간순 분할도 시도한다.
- **산출물:** 누수 비율 통계, 그룹 분할 결과 표 (부록 또는 5절 보강).
- **판정 기준:** 그룹 분할에서 운영점 넘김률이 5%p 이상 오르거나 Macro-F1이 0.5%p 이상 떨어지면 주 결과를 그룹 분할 기준으로 교체하고 기존 결과는 보조로 돌린다.
- **논문 반영:** 4.1절, 한계 절.

### T6. RGB CNN 설계 점검 (RQ1 결론의 범위 확정)
- **목적:** 이미지 단독 탐지가 진 이유가 "이미지 표현 일반"이 아니라 패딩 희석이나 전역 평균 풀링 같은 설계 결함인지 확인한다.
- **방법:**
  - 요청 길이 분포와 점유되는 행 수 통계를 낸다.
  - 파라미터 수를 비슷하게 맞춘 ablation: (a) 전역 평균 풀링 → 전역 최대 풀링, (b) 점유 행만 잘라 입력, (c) 1차원 정렬 변형 (이미지 폭 조정).
  - 모든 변형을 같은 CV 설정에서 평가한다.
- **산출물:** ablation 표 (부록 또는 5.1절 보강).
- **판정 기준:** 변형 중 하나가 char-CNN과의 격차를 절반 이상 줄이면 RQ1 서술을 "본 인코딩의 설계 한계"로 바꾸고 이후 캐스케이드 실험에서 개선된 1차 사용 여부를 결정한다. 격차가 유지되면 "본 논문의 인코딩과 얕은 CNN에서"로 한정해 결론을 유지한다.
- **논문 반영:** 3.1절, 5.1절, 결론의 일반화 표현 ("이미지 단독 탐지는 텍스트 모델을 대체하지 못한다" → 범위 한정).

### T7. 기준선 보강: "표현 이질" 가설 검증
- **목적:** 제목과 기여의 핵심 주장을 대조군으로 검증한다.
- **방법:**
  - **동질 캐스케이드:** 1차를 소형 char-CNN으로 대체한다. 지연 매칭 버전과 파라미터 매칭 버전 두 가지. 2차는 동일 char-CNN. 같은 평가(ρ_ε, S)를 적용한다.
  - **저비용 비신경 기준선:** char n-gram TF-IDF 또는 해싱 + 선형 모델의 단독 Macro-F1과 지연(순전파와 end-to-end). 가능하면 이 모델도 1차로 사용한 캐스케이드를 시험한다.
  - **오류 상보성:** 1차와 2차의 동시 오류율, Q-통계 등을 이질 조합과 동질 조합에서 비교한다.
- **산출물:** 기준선 비교 표 (신규 Table), 상보성 지표.
- **판정 기준(사전 지정):** 같은 지연 예산에서 이질 1차가 동질 1차보다 ρ_ε가 낮거나 S가 높지 않으면, 제목과 기여에서 "표현 이질적"을 약화하고 "음성 결과와 평가 방법론" 중심으로 재서술한다.
- **논문 반영:** 제목, 서론 기여, 5절 신규 소절, 논의.

### T8. 라벨 감사 보강
- **목적:** 5.7절 결론("71% 라벨 불일치")의 신뢰도 확보.
- **방법:**
  - 110건의 추출 방식을 명시한다 (꼬리 전체인지 표본인지, 모집단 크기, 꼬리 정의: 1차 확신도 ≥0.99이고 1차 오답, 2차 정답). 이전 표본과 모집단 크기(약 700건)를 대응시킨다.
  - 판정 기준표(정의, 예시, 경계 사례)를 만든다.
  - 보안 경험자 2인이 독립 판정하고 Cohen's κ를 보고한다. LLM 판정은 보조 도구로 쓰고 사람 판정과의 일치도를 함께 보고한다.
  - 라벨 정제 파이프라인(30,280행 제거)의 기준과 감사 결과의 관계를 정리한다. 제거된 행과 남은 행의 불일치율을 비교한다.
  - SR-BH 원논문에서 라벨 생성 절차(규칙 기반 자동 라벨 여부)를 확인해 4.1절에 기록한다.
  - 가능하면 사람이 검증한 소규모 clean 시험 서브셋에서 게이트 곡선을 재평가해 라벨 잡음의 영향을 분리한다 (탐색).
- **산출물:** Table 8 갱신, κ, clean 서브셋 결과 (선택).
- **판정 기준:** 사람 판정의 불일치율이 LLM 판정과 20%p 이상 다르면 LLM 중심 결론을 삭제하고 사람 판정 중심으로 다시 쓴다.
- **논문 반영:** 4.1절, 5.7절, 논의의 라벨 잡음 문단, 한계 절 (LLM 한계 문장 갱신).

### T11. 시험 집합 사용 감사와 구성 선택 재판정
- 사전 기준 (2)(1차 학습 방식 선택: 3.3% 헤드라인 배수 1.19배 이상, Macro-F1 손실 0.3%p 이하)를 CV의 검증 부분에서 다시 판정한다. 시험 집합 결과는 확인용으로 격하한다.

### T12. 수치 재검증 체크리스트 (모든 수정 후 반복)
이번 검수에서 재계산이 맞은 항목은 유지하고, 다음 항목은 반드시 해결한다.

## 3. 우선순위 P1: 원고 수정 (실험 결과 확정 후 반영)

### T13. 이전 실험의 출처 처리
- 5.07배, 8%, 0.9804 대 0.9954, 13.6배, 14.8배의 출처를 확정한다. 본인의 선행 논문 또는 학위논문이면 인용하고, 중복 게재 여부와 학회 규정을 확인한다.
- 인용이 불가능하면 이전 실험의 방법과 데이터를 부록에 완결되게 적는다. 본문 서술은 "이전 실험"이라는 표현 대신 구체적인 인용 또는 부록 참조로 바꾼다.
- RQ 번호(현재 RQ1, RQ5)를 정리한다. 이 논문의 질문만 RQ1, RQ2, RQ3 …으로 다시 번호 매기거나 RQ 표기를 없앤다.

### T14. 주장 수위와 문장 수정 목록
- 초록과 결론의 "넘김 판단은 개선하지 못했다": T3 결과에 따라 수위를 조정한다. 최소한 "사전 기준을 충족하지 못했다(검정력 한계 포함), 탐색 분석에서는 G2가 …"로 균형 있게 쓴다.
- 서론과 결론의 "이미지 단독 탐지는 텍스트 모델을 대체하지 못한다": T6 결과 후 "본 인코딩과 얕은 CNN에서"로 범위를 한정한다.
- "배포 조건" 표현: T4 결과 후 "스캐너 기준 정상 트래픽에서의 추정"임을 명시한다.
- 논의의 "상한 자체가 낮아졌다": T2 결과에 따라 삭제 또는 수정한다.
- "1차 내부 표현까지 넣은 라우터가 실패했다 → 2차가 맞힐지를 1차 정보만으로 예측하기 어렵다": "시도한 라우터(로지스틱 회귀)에서는"으로 한정한다 (T3에서 GBDT 라우터 결과에 따라 갱신).
- 3.6절 "하한이다": 검증 목적함수 기준임을 명시하거나 문장을 삭제한다.
- 4.1절 쿠키 실험: p=0.17은 "차이를 검출하지 못했다"이지 "길이 효과의 증거"가 아니므로 문장을 수정한다.
- 3.2절 ViT와 조기 종료 문장: 부록으로 옮겨 근거를 붙이거나 삭제한다.
- 영문 초록의 "pre-registered"를 "pre-specified"로 바꾸고 커밋 해시를 본문에 기재한다.
- 기여 6개를 3개(배포 조건 평가 방법론, SR-BH 사례 연구, 음성 결과 두 건)로 압축한다. T7 결과에 따라 "표현 이질"의 위상을 결정한다.
