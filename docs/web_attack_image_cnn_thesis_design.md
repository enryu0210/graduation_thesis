## 1. 연구 질문 (Research Questions)

### 1.1 ⚠️ RQ 번호 규약 — 재배열 금지

RQ 번호가 **파일명에 박혀 있다**(`05_evasion_attacks_rq2`, `06_..._rq4`, `10_..._rq3`).
전면 재번호는 파일명 + 12개 문서 136곳의 상호참조를 흔든다.
→ **ID 는 고정하고, 새 질문은 뒤 번호로 추가**한다. 논문 본문의 **서술 순서**만 §1.3 을 따른다.

### 1.2 RQ 표 (2026-08-06 개정)

| ID | 질문 | 상태 |
|----|------|------|
| **RQ1** | 웹 공격 페이로드(SQLi, XSS, CmdI)를 바이트 이미지로 변환한 탐지는, 텍스트 기반 모델(char-CNN/BiLSTM, TF-IDF+전통 ML) 대비 **정확도–비용 Pareto 상 어디에 위치하는가?** | ✅ 답 완료 — **음성 결과** (F1·F2·F3) |

| **RQ4** | 탐지 신호가 콘텐츠에서 사라질 때(인코딩→암호화), 내용 기반 이미지 탐지는 **어디서 원리적으로 붕괴하는가?** (→ 경계의 정량 규명) | ✅ RQ4a 완료(F12) / ⚠️ RQ4b 포화(G6) |

### 1.3 논문 서술 순서

```
RQ1 (음성 결과: 이미지 단독은 진다)
  └─▶ RQ5 (그래서 캐스케이드 — 이 논문의 제안)
        ├─▶ RQ2 (그 제안은 회피에 얼마나 버티는가 + 비용 공격)
        ├─▶ RQ3 (방어를 붙이면 어떻게 되는가)
        └─▶ RQ6 (제안 구조에서만 공짜로 얻어지는 능력)   ※ 실측 시
RQ4 (별도 축: 내용 기반 탐지 자체의 경계)
```

### 1.4 ⚠️ RQ1 개정에 대한 정직성 원칙 (HARKing 방지)

RQ1 은 원래 *"이미지 기반 CNN 이 텍스트 모델과 **유사하거나 더 나은** 성능을 보이는가"* 였고,
실측 답은 **"아니오"**(F1)였다. 결과를 본 뒤 질문을 비용 축으로 바꾸는 것은
사후가설(HARKing)이 될 수 있다. → **다음 서술 원칙을 반드시 지킨다.**

1. 원 RQ1 문구와 **그 답이 '아니오'였음을 그대로 보고**한다. 숨기거나 바꿔치지 않는다.
2. RQ5(캐스케이드)는 **그 음성 결과에서 파생된 질문**임을 명시한다.
3. Phase 12 이후의 판정 기준(H5·H6·H7)은 **실측 전에 문서로 고정**한다(docs/11 §7).

> 이렇게 쓰면 "질문을 슬쩍 바꾼 것"이 아니라 **"음성 결과에서 출발한 설계"**가 되어,
> 선행 8편 중 유의성 검정이 0편인 상황(docs/12 §0)에서 오히려 방법론적 강점이 된다.

### 1.5 범위 가정

- **다중 클래스 분류**(정상 / SQLi / XSS / CmdI). 시간 부족 시 이진(정상 vs 공격)으로 축소 가능.
- **G4 적응형 공격(방어를 알고 설계된 공격)은 수행하지 않는다** — 한계로 명시(docs/11 §9).

## 4. 페이로드 → 이미지 변환

**Step 1 — 정규화**: 페이로드 문자열 → UTF-8 바이트 시퀀스

**Step 2 — 2D 리셰이프** (Nataraj 방식 차용)
- 고정 폭 48 → 48×48. 짧으면 zero-padding, 길면 truncation. 픽셀 = 바이트값 0~255 → 0~1 정규화
- 픽셀 `(r,c)` ↔ 바이트 오프셋 `r*48+c` 는 **전단사**(docs/08 §2) — Grad-CAM 역변환의 근거

**Step 3 — RGB 채널 enrichment** (교수 요구, 채택됨)
- R = raw byte / G = 문자 클래스 / B = local n-gram 엔트로피
- **효과 확정(F2)**: gray→RGB MCC 0.9493 → 0.9762 (**+2.69pp**, adj p=0.0037~0.0201)
- **단, 채널 조합 간 우열은 판정 불가(F3)** — 6쌍 전부 adj p ≥ 0.88. "어떤 조합이 낫다"고 쓰지 말 것.
- 인코더는 `src/imaging/channel_encoders.py` **레지스트리**(교체형 ablation 기반)

## 5. 모델 아키텍처

- **제안 모델 = 캐스케이드 탐지기** (1차 RGB CNN 전량 → 확신도 < τ 인 소수만 2차 char-CNN)
  - 1차 **RGB CNN**: 얕은 CNN(Conv 32→64→128, BN, ReLU, MaxPool ×3, GAP, FC+Softmax), 48×48×3, 93,988p
  - 2차 **char-CNN**: 텍스트 베이스라인 중 정확도 최고(docs/04 §5.1)
  - **학습 없음** — 기존 `_bal` 체크포인트 2개를 조합. τ→0 은 CNN 단독, τ→1 은 char-CNN 단독으로 수렴
  - τ 는 **val 에서 확정 후 test 에 1회 적용**(test 로 고르면 누수)
- **비교 기준**: RGB CNN 단독 / gray CNN / char-CNN / BiLSTM / TF-IDF+RF·XGBoost·LogReg
- **미채택**: ViT·hybrid(CNN stem+Transformer) — CNN 대비 +0.12pp, p=1.0000 (F13, docs/08)

### 5.1 ⚠️ 용어 규칙 (혼동 사고 후 확정)

- **`제안 CNN` 이라는 말은 쓰지 않는다.** (ㄱ)제안 모델과 (ㄴ)캐스케이드 1차 부품 두 뜻으로 읽혀
  실제 혼동이 났다(docs/10 §0.1).
- `RGB CNN` = 48×48×3 단일 CNN(비교 기준) · `gray CNN` = 1채널 판본 · `얕은 CNN` = 아키텍처 지칭
- **`hybrid`(모델) 와 `cascade`(배치 구조)는 다른 것** — 이름 섞지 말 것
- 과거 문서의 회피 수치 0.594/0.5944/0.0022 는 **gray 실측**이다. RGB 기준선은 **0.5981**

## 6. 실험 설계

### 6.1 RQ1 — 정확도–비용 Pareto 위치
- 지표: Accuracy, Macro-F1, **MCC**, PR-AUC, ROC-AUC + attack-focused(benign-evasion/FPR)
- **비용 지표**: 추론 처리량(/s)과 지연(ms/sample) — 이 축이 결론의 본체
- 5-fold CV(train/val/test 를 풀로 합쳐 재분할) + paired t-test + **Holm 보정**
- ⚠️ 단일 split 은 실행 간 ±0.11pp 흔들림(cuDNN 비결정성) → 우열 주장은 **반드시 CV 로 판정**
- ⚠️ **기본 lr=1e-3 은 CNN 기준값** — ViT 계열은 이 값에서 발산. lr 을 맞춰서 비교할 것(docs/08 §9.1)

### 6.2 RQ5 — 캐스케이드 (제안 모델)
- τ 스윕 → **정확도–비용 곡선**. 양 끝점이 두 단독 모델로 수렴함을 단위 테스트로 고정
- τ 선택 규칙: `--select match-teacher | budget`
- **oracle 라우팅**(1차가 틀린 것만 정확히 승급)을 상한으로 함께 보고 → 게이트 품질의 개선 여지
- 지연 측정: **5라운드 × 20회의 중앙값**(단발 측정은 60% 흔들림, docs/09 §9.7)

### 6.3 RQ2 — 회피 공격
**feature-space 와 problem-space 를 구분**한다.
- **Problem-space(주 실험)**: 주석 삽입 `/**/`, 대소문자 랜덤화, 공백/탭 치환, URL/이중 인코딩,
  동치 SQL 토큰 치환, XSS `String.fromCharCode`. 누적 변형 k=1..5
- **Feature-space(보조)**: FGSM/PGD — 생성된 적대적 이미지가 유효 바이트로 역변환되지 않을 수 있음을 명시
- 주 지표: **any-misclass**(benign-evasion 은 전 구성 바닥 ~0 이라 판별력 없음, F8)
- **캐스케이드 고유**: 조건별 `escalation_rate` 를 함께 기록 → 비용 기반 공격 측정

### 6.4 RQ3 — 방어
- 적대적 증강: 회피 변형을 정답 라벨과 함께 **치환식**으로 학습 데이터에 주입(비율 ρ)
- **변형 계열 분할**: S-0(전 계열 학습) vs **S-A(인코딩 계열 held-out)** → 미지 변형 일반화 측정
- **1·2차 양쪽** 방어본을 조립하고 τ 를 그 구성의 val 에서 **재선택**(확신도 분포가 달라짐)
- 반드시 병기: clean 정확도 하락, FPR, **그리고 에스컬레이션 비율 변화**(캐스케이드의 실제 대가)

### 6.5 RQ4 — 암호화 경계
- 단계적 신호 소멸: 평문 → 인코딩 → 고정키 XOR → AES
- ⚠️ **초점 재조정(2026-08-06)**: "신호가 흐름으로 이동한다"는 결론은 **선행이 이미 도달**해 있다
  (Kutlimuratov et al. 2026 은 처음부터 흐름 메타데이터만 사용). → 우리 기여는 도착지가 아니라
  **경계의 정량 증명**(F12)으로 좁힌다. 상세는 docs/12 §3.1, docs/06.

## 11. 논문이 주장하는 기여 (4가지) — 주장 강도 확정

docs/12 의 선행 대조를 반영해 **과장을 걷어낸 최종 문구**다.

| # | 기여 | 쓸 문구 | ❌ 쓰면 안 되는 문구 |
|---|---|---|---|
| C1 | **표현 이질적 캐스케이드** | "이미지 표현과 텍스트 표현을 잇는 캐스케이드로, 같은 정확도를 **5.07배 싸게** 얻는다" | "이미지 기반이 더 정확하다" |
| C2 | **τ 연속 스펙트럼** | "τ 하나가 clean 정확도뿐 아니라 **공격 하 강건성에서도** 두 단독 모델 사이를 연속 이동한다(0.364↔0.556)" | — |
| C3 | **problem-space slowdown 공격** | "DeepSloth 가 보인 slowdown 공격이 웹공격 탐지 캐스케이드에서도 성립함을 실측했다. 단 **모델 접근 없이, 실제로 동작하는 페이로드 변형만으로** 2.17배를 달성했다" | "새로운 공격면을 **발견**했다" |
| C4 | **게이트 품질의 상한 정량화** | "확신도 게이트는 oracle 대비 **14.8배 과잉** 승급한다 — 개선 여지의 상한을 못 박았다" | — |
| (C5) | **표현 불일치 회피 탐지** ⏳ | "캐스케이드는 이미 2차를 돌리므로 **추가 비용 정확히 0**(모드 A)으로 회피 시도를 판정한다" | "표현 불일치를 쓰는 것이 새롭다" |

**정직하게 함께 쓸 한계**
- 이미지 단독은 텍스트 모델에 **유의하게 진다**(F1)
- clean 탐지 **상보성 이득 없음**(F4) — 캐스케이드의 기여는 탐지집합 확장이 아니라 비용 축소
- 적대적 증강은 **본 변형만 암기**(F9)
- 소규모 배포에서는 **char-CNN 단독으로 충분**하다
- **적응형 공격 미수행**(G4)
- 성능 차이는 표면 토큰 포화 상태의 트랙에서 측정됐다(docs/04 §7)
