# 웹 공격 페이로드 이미지화 기반 CNN 탐지 및 적대적 강건성 연구
### 학부 졸업논문 설계 문서

---

## 0. 연구 동기

- 전공: 인공지능, 관심 분야: 보안
- 세부 관심사: 악성코드·피싱 탐지 / AI 모델 자체에 대한 공격·방어
- 논문 방향: 새로운 탐지·방어 모델 개발 (실험·구현 위주)
- 출발점: 악성코드 바이너리를 그레이스케일 이미지로 변환해 CNN으로 분류하는 기법(Nataraj et al.)을 웹 보안 도메인으로 확장하여, 웹 공격 페이로드 탐지에 적용

이 설계는 위 관심사 두 가지(탐지 모델 개발 + AI 모델의 공격/방어)를 하나의 파이프라인 안에서 다루도록 구성했습니다.

## 1. 연구 질문 (Research Questions)

| ID | 질문 |
|----|------|
| RQ1 | 웹 공격 페이로드(SQLi, XSS, Command Injection)를 바이트 단위 그레이스케일 이미지로 변환했을 때, 기존 텍스트 기반 탐지 모델(문자 임베딩 CNN/BiLSTM, TF-IDF+전통 ML 등) 대비 이미지 기반 CNN이 유사하거나 더 나은 탐지 성능을 보이는가? |
| RQ2 | 이 이미지 기반 탐지 모델은 실제 공격자가 WAF를 우회할 때 사용하는 회피 기법(인코딩, 주석 삽입, 대소문자 변형 등)에 얼마나 취약한가? |
| RQ3 | 회피 공격 샘플을 활용한 adversarial training을 적용하면 강건성이 얼마나 개선되며, 이 과정에서 정상 트래픽 오탐률과 기존 탐지 정확도는 얼마나 희생되는가? |
| RQ4 | **탐지 신호가 콘텐츠에서 사라질 때(인코딩→암호화), 바이트-이미지 CNN의 내용 기반 탐지는 어디서 원리적으로 붕괴하며, 탐지를 유지하려면 신호는 어디로(흐름 side-channel) 이동해야 하는가?** (→ `docs/06_encryption_boundary_rq4_design.md`) |

> **범위 가정**: 학부 졸업논문(한 학기 내외) 범위를 고려하여 **다중 클래스 분류(정상 / SQLi / XSS / Command Injection)** 로 설계함. 시간이 부족할 경우 이진 분류(정상 vs 공격)로 범위를 축소 가능.
>
> **RQ4 추가 배경 (2026-07-09 교수 미팅)**: "이미지 변환 기반 선행연구가 이미 많다 → 신규성이 약하다. 정확도가 낮아지더라도 *기존이 탐지 못하던 것*을 다루거나 개선을 보여야 한다"는 지적. 교수 제안(암호화 통신 상 페이로드 탐지)을 그대로 받으면 **암호화 시 페이로드 바이트가 랜덤 암호문이 되어 내용 기반 탐지가 원리적으로 불가능**하다는 모순이 있다. RQ4는 이 모순 자체를 *발견*으로 전환한다 — "암호화가 내용 기반 이미지 탐지의 경계임을 정량 증명(RQ4a) + 신호가 흐름 side-channel로 이동함을 실측(RQ4b)". 상세는 06 문서.

## 2. 전체 파이프라인

```
① 데이터 수집·전처리 (정상/공격 페이로드 정규화)
        ↓
② 페이로드 → 이미지 변환 (바이트 단위 그레이스케일 매핑)
        ↓
③ CNN 탐지 모델 학습·평가  ── RQ1: 탐지 성능 비교
        ↓
④ 회피 공격 생성·평가      ── RQ2: 문제공간(problem-space) 변형 공격
        ↓
⑤ 적대적 방어 학습·재평가  ── RQ3: 강건성-성능 트레이드오프
        ↓
⑥ 인코딩→암호화 신호 소멸 실측 + 흐름 이미지화 ── RQ4: 내용 탐지의 경계와 신호 이동
```

## 3. 데이터셋 설계

| 용도 | 소스 | 비고 |
|---|---|---|
| 공격 페이로드 (SQLi/XSS/CmdI) | Kaggle SQLi-XSS-CommandInjection dataset (약 5만 건) | 이미 3개 클래스로 라벨링됨 |
| 웹 트래픽 (HTTP 요청) | CSIC 2010 HTTP dataset | 정상/이상 요청 모두 포함, 실제 요청 구조 반영 |
| 페이로드 다양성 보강 | PayloadsAllTheThings, OWASP XSS filter evasion cheat sheet | 특정 패턴 과적합 방지용 보조 샘플 |
| 정상(benign) 트래픽 | CSIC 2010 정상 요청 + 필요시 합성 트래픽 | 클래스 불균형 주의 |

**전처리 체크리스트**
- URL 디코딩 · HTML 엔티티 디코딩으로 표기 정규화
  - 단, 이 단계가 RQ2 공격 실험의 난이도를 좌우하므로 "디코딩 적용 vs 미적용" 두 버전을 비교하는 ablation 고려
- 완전 중복 페이로드 제거 (제거 전/후 성능을 함께 보고하면 평가 신뢰도 상승)
- Train / Val / Test = 70 / 15 / 15, stratified split
- 클래스 불균형 시 class weight 또는 oversampling 적용

## 4. 페이로드 → 이미지 변환 설계 (핵심 기여 지점)

**Step 1 — 정규화**: 페이로드 문자열을 UTF-8 바이트 시퀀스로 인코딩

**Step 2 — 2D 리셰이프** (Nataraj et al. 방식 차용)
- 고정 폭 `W` 결정 (예: 32) — 데이터셋 페이로드 길이 분포(EDA) 기반으로 결정
- 높이 = `ceil(바이트 수 / W)`
- 목표 크기(예: 32×32)보다 짧으면 zero-padding, 길면 truncation
- 픽셀 값 = 바이트 값(0~255) → 0~1 정규화

**Step 3 (확장 / ablation) — RGB 채널 enrichment**
- R 채널: raw byte 값
- G 채널: 문자 클래스(영문자/숫자/특수문자) one-hot 인코딩 강도
- B 채널: local n-gram 엔트로피
- 시간 여유가 있을 때 "단순 그레이스케일 vs RGB 강화" ablation으로 확장 가능

> 이 변환은 악성코드 이미지 분류(Nataraj 방식)를 그대로 재사용한 것이며, 기존 웹 공격 탐지 연구(대부분 문자 임베딩/시퀀스 모델)와 차별화되는 지점 — 관련연구 챕터에서 명확히 서술할 것.

## 5. 모델 아키텍처

- **제안 모델**: 얕은 CNN (Conv 32→64→128, BatchNorm, ReLU, MaxPool × 3, GAP, FC+Softmax, 4-class)
- **비교 베이스라인**
  - 전통 ML: TF-IDF/n-gram + XGBoost, RandomForest
  - 텍스트 딥러닝: character-level CNN, BiLSTM
  - (선택) Transfer learning: 사전학습 경량 CNN(MobileNetV2) fine-tuning

## 6. 실험 설계

### 6.1 RQ1 — 탐지 성능
- 지표: Accuracy, Macro F1, 클래스별 Precision/Recall, Confusion Matrix, ROC-AUC(OvR)
- 실용성 지표: 추론 지연시간(throughput) — 실제 WAF 배포 가능성 논의에 필요
- 5-fold cross validation, 베이스라인 대비 paired t-test로 유의성 확인

### 6.2 RQ2 — 회피 공격
핵심 설계 포인트: **feature-space 공격과 problem-space 공격을 구분**

- **Problem-space 공격 (주 실험)**: 실제로 동작하는 페이로드를 만드는 규칙 기반 변형
  - 주석 삽입 (`/**/`), 대소문자 랜덤화, 공백/탭 치환
  - URL/이중 인코딩
  - 논리적으로 동일한 SQL 토큰 치환 (예: `OR 1=1` → `OR 2=2-1`)
  - XSS 문자열 인코딩 (예: `String.fromCharCode`)
  - (선택) 유전 알고리즘으로 변형 조합을 탐색해 최적 우회 조합 탐색 (WAF-A-MoLE 방식 참고)
- **Feature-space 공격 (보조/비교용)**: FGSM/PGD로 이미지 픽셀을 직접 교란
  - 한계: 생성된 "적대적 이미지"가 실제 유효한 바이트 시퀀스로 역변환되지 않을 수 있음 → 이 한계를 논문에서 명시적으로 논의
- 평가지표: Attack Success Rate (ASR) = 탐지를 회피한 공격 샘플 비율

### 6.3 RQ3 — 방어
- Adversarial training: RQ2에서 탐지를 회피한 변형 페이로드(의 이미지)를 정답 라벨과 함께 학습 데이터에 추가해 재학습
- 평가: 방어 전/후 ASR 비교
- **중요**: 정상 트래픽 오탐률과 원래 클래스 정확도가 얼마나 희생되는지(트레이드오프)까지 반드시 함께 보고
