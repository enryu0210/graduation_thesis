## 0. 집필 도구에 주는 규칙 (반드시 지킬 것)

1. **사전 판정 결과는 판정 문장 그대로 쓴다.** 기준을 못 넘은 것을 "경향이 있다"·"개선됐다"로 올려 쓰지 않는다. 기준에 없던 분석은 "사후 분석" 또는 "병기"라고 밝힌다.
2. **"개선"이라는 단어는 사전 판정을 통과한 것에만** 쓴다. 넘김 판단(G2)의 "개선"은 E13 에서 확인되지 않았다(§5) → **이 논문에서 넘김 판단에 "개선"을 쓰지 않는다.** "유사 연구 대비 개선"도 쓰지 않는다.
3. **속도 배수에는 항상 조건을 붙인다**: 장치(CPU 단일 스레드·배치 1), 기준 모델, 분포(실사용자 정상 / 검증 분포), 평균 방식(합산 = fold 배수의 조화평균). "합산 배수"가 헤드라인이고 산술평균은 괄호 병기.
4. **seed 를 밝힌다.** 한 seed 에서만 성립한 결과는 "seed 42 한정"이라고 쓴다.
5. **RQ1 의 답은 "아니오"다.** 이미지 CNN 이 텍스트 모델보다 유의하게 낮았다는 음성 결과를 그대로 보고하고, 캐스케이드 연구가 거기서 파생됐다고 쓴다(질문을 사후에 바꾼 것처럼 쓰지 않는다).
6. FPR 은 **실사용자 층과 스캐너 층을 나눠** 쓴다(SR-BH Normal 의 대부분이 스캐너 탐침이다).
7. MCC 는 쓰지 않는다(지도교수 지시로 제거). 기준 지표는 Macro-F1.
8. 그림·표 캡션은 영문, 본문은 한국어. 참고문헌은 영문.

## 1. 논문 뼈대

- **제목(마스터 문서 기준, 2026-10-27)**: *딥러닝 캐스케이드 웹 공격 탐지: 넘김 판단의 한계와 배포 조건별 속도–정확도 교환의 재평가*
  - 원고 10-30 판은 *문자 수준 CNN과 DistilBERT 기반 캐스케이드 웹 공격 탐지의 속도–정확도 교환 분석* 을 쓰고 있다. 둘 중 무엇을 쓸지는 사용자(저자)가 정한다 — 둘 다 "개선"을 넣지 않았다는 점은 같다.
- **데이터**: SR-BH 2020, 4클래스(Normal · SQLi · CodeInjection · CommandInjection). 입력 = URI + body(F2). 봉인 test 를 뺀 train+val 풀(226,048행)에서 5-fold 교차검증(`--exclude-test`).
  - CommandInjection(CmdI)은 2.1%(풀 3,886건)의 최소 클래스.
  - Normal 의 대부분은 스캐너 탐침이고, 실사용자 정상은 풀 550건(fold 당 약 110건)이다.
- **연구 질문(논문 서술 순서)**
  - **RQ1** 바이트 이미지 CNN 이 텍스트 모델과 비슷하거나 나은가 → **아니오**(char-CNN 보다 Macro-F1 약 9%p 낮음).
  - **RQ5** (RQ1 에서 파생) 가벼운 1차 + 무거운 2차 캐스케이드가 2차 단독 정확도를 더 싸게 얻는가. 두 축: ① 속도–정확도 교환 ② 넘김 판단(게이트).
  - RQ2·RQ3·RQ6 은 2기(이전 데이터) 결과. RQ4 는 논문에서 뺐다(번호는 결번).
- **제안 구성**: 1·2차 모두 딥러닝(2026-10-27 확정). 고전 ML(TF-IDF+LR)은 비교 기준으로만. 결과가 가장 좋은 구성은 **char-CNN → DistilBERT(DL-A)** 이지만, 사전 기준을 두 seed 모두 통과한 것은 아니다(§4).

### 1.1 용어

| 기호 | 뜻 |
|---|---|
| B0 | 표준 넘김: 1차 최대 확률 < τ 이면 2차로(τ 하나) |
| G2 | 클래스별 τ: 1차가 예측한 클래스마다 τ 를 따로 둔다 |
| r_A · r_N | 공격 요청·정상 요청의 넘김률 |
| E_π | 배포 기대 넘김률 = 0.033·r_A + 0.967·r_N (배포 공격 비율 π = 3.3%) |
| S_R | 기준 모델 R 대비 배수 = t_R / (t1 + E_π·t_R) |
| 합산 배수 S̄ | fold 배수의 **조화평균**(= 평균 비용의 역수). 헤드라인은 이것. 산술평균은 큰 fold 가 부풀린다 |
| 운영점 규칙 | fold 마다 val 에서 "val F1 ≥ 2차 val F1 − 0.5%p 인 점 중 val E_π 최소"를 고르고 fold-test 에 한 번 적용(`gate_confirm.secondary_rule`) |
| 실사용자 판본 | r_N 을 실사용자 정상 층으로 잰 값(검증 분포 판본은 스캐너 위주 정상) — **판정은 실사용자 판본** |
| 보정 t | Nadeau–Bengio 보정 t 검정(fold 간 학습 집합 중복 보정) |
| 지연 | CPU 단일 스레드·배치 1·p50, 전처리 포함·패딩 없음(`latency_fair.py` 방식) |

### 4.3 각 결과의 쓸 문장

**DL-B**: ✅ "초경량 1차는 넘김이 30% 로 늘어 2.13배에 그쳤고 F1 이 0.45%p 떨어져 기준을 못 넘었다."

**DL-C**: ✅ "char-CNN 내부의 k3 분기에 보조 헤드를 결합 학습하면 두 seed 모두 char-CNN 단독과 같은 정확도를 3.5~3.6배 빠르게 냈다."
- ⚠️ 이득의 원천은 넘김이 아니라 **보조 헤드 자체**다(seed 42 다섯 fold 중 셋, seed 43 전 fold 가 넘김 0%). → "2차 모델 압축(결합 학습한 k3 출구)"으로 쓴다.
- ❌ "넘김 판단 개선" · ❌ "유사 연구 대비 개선".
- k3 단독 대조(같은 크기를 혼자 학습) 0.9748 은 보조 헤드보다 1.01%p 낮았다(보정 p 0.34). 원인이 표현력인지 학습 안정성인지는 가리지 못했다(E16 미실시, §5).

**DL-A (주 결과)**:
- ✅ "char-CNN → DistilBERT 캐스케이드는 실사용자 정상 기준 평균 비용으로 재구현 DistilBERT 단독보다 10.6~12.3배 빨랐고(두 seed 모두 다섯 fold 전부 1배 초과), F1 손실은 seed 42 −0.03%p, seed 43 −0.32%p 였다. 사전 기준(손실 0.3%p 이내)은 seed 42 에서만 충족했고 확인 seed 43 에서는 0.02%p 차로 재현되지 않았다."
- ✅ seed 43 실패의 내용: 캐스케이드 F1 은 0.9911 → 0.9914 로 그대로였고, 기준인 DistilBERT 단독이 0.9914 → 0.9947 로 올라갔다(3 에폭 미세조정의 seed 편차). 캐스케이드는 트래픽의 약 93% 를 char-CNN 판정으로 끝내므로 2차가 강해져도 상한이 묶인다.

4. 라벨 감사(70.9%)는 대형 언어모델 1인 판정 — 2인 독립 감사(T8)는 하지 않았다(사용자 결정 2026-10-31: 논문 축 밖이라 생략, 성능 수치는 원 라벨 기준이라 영향 없음). 이 값은 결과 절이 아니라 이 한계 절에서만, "가능성" 수준으로 쓴다.
5. 적응형 공격은 하지 않았다. 비용 기반 공격은 고정 변형(E15)만.
6. 단일 데이터셋(SR-BH 2020). Normal 의 대부분이 스캐너 탐침이다.
7. 1차원 합성곱 1차·선형 1차는 seed 42 한 번의 교차검증.
