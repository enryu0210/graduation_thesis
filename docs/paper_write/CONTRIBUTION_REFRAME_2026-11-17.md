## 1. "공격 클래스 오탐"의 정의 — ⚠️ 먼저 확정할 것

이 데이터에서 "오탐"은 두 가지로 읽힌다. **두 방향의 결과가 반대**라서 교수님이 뜻하신 것을 확인해야 한다.

| 정의 | 무엇 | 캐스케이드 결과 (seed 42 / 43, 5-fold 합산) | 출처 |
|---|---|---|---|
| **(가) 공격 종류 간 오탐** (권장) | 다른 공격·정상을 특정 공격 클래스로 잘못 경보 — 예: SQLi → CmdI | SQLi→CmdI **192 → 123 / 252 → 113** · Normal→CmdI 38 → 17 / 50 → 23 · CmdI 정밀도 **95.18 → 97.07% / 93.90 → 97.32%** | 초안 Table 3 · docs/14 §8.37 |
| (나) 정상 오탐(benign false alarm) | 정상을 공격으로 판정 | **206 → 247 / 140 → 164 (늘어남)** · 단 실사용자 FPR 은 2.00 → 2.00% / 1.27 → 1.27% 로 그대로, 늘어난 몫은 스캐너 층(0.35 → 0.42% / 0.24 → 0.28%) | 초안 Table 3 |

- (가)로 잡으면 주 기여가 성립한다. (나)로 잡으면 **오히려 악화**라 주 기여가 될 수 없다.
- 어느 쪽이든 (나)의 증가는 본문에서 **맞교환으로 한 문장 밝혀야 한다**(투고 검토 🔴4 — 숨기면 "불리한 숫자 은폐"로 읽힌다). 다행히 실사용자 층에서는 변화가 없다는 점이 방어 근거다.

## 2. 기여 후보 상세 — 쓸 수 있는 것

### A. (주 기여) 공격 종류 간 오탐 감소 · CmdI 경보 정밀도 향상

| 지표 (5-fold 합산 226,048행) | seed 42: char-CNN → 캐스케이드 → DistilBERT 단독 | seed 43 |
|---|---|---|
| SQLi → CmdI 거짓 경보 | 192 → **123 (−35.9%)** → 99 | 252 → **113 (−55.2%)** → 2 |
| 공격 종류 혼동 전체 | 266 → **196 (−26.3%)** → 167 | 359 → **220 (−38.7%)** → 59 |
| CmdI 정밀도 / 재현율 | 95.18 / 98.52 → **97.07 / 98.45** | 93.90 / 98.58 → **97.32 / 98.52** |
| CmdI F1 | 0.9682 → **0.9776 (+0.94%p)** | 0.9618 → **0.9792 (+1.74%p)** |
| DistilBERT 단독 감소분 중 캐스케이드가 회수한 비율 | **74%** | **56%** |
| 2차로 넘긴 비율(시험 전체) | 0.7~0.8% | 0.7~0.8% |
| 공격 차단 실패(공격→정상) | 791 → 697 | 839 → 743 |

- seed 44·45: CmdI F1 +0.29·+0.26%p(초안 5.3절 1)) → **4 seed 모두 같은 방향**. 단 44·45 의 혼동 건수·정밀도는 문서에 없다(§3).
- **왜 싸게 회수되나**: DistilBERT 가 고친 오답에서 char-CNN 확신도 중앙값 0.775·0.766, 0.99 이상은 15.1%·10.7% 뿐(전체 요청은 97.0%) → char-CNN 은 SQLi/CmdI 사이에서 흔들릴 때 스스로 덜 확신한다. 그래서 확신도 넘김만으로 골라 보낼 수 있다(docs/14 §8.36(3)).
- **사전 등록 상태(HARKing 방어에 중요)**:
  - DistilBERT 가 SQLi→CmdI 를 줄인다는 발견 자체는 **E11 판정 뒤 사후 분석**(§8.36).
  - 그러나 "캐스케이드가 이 이득을 얼마나 물려받는가"는 **측정 전(2026-10-28, 커밋 b341e9f)** `05_distilbert_tok128_cmdi_plan.md` §4 에 해석 문장까지 미리 적어 두고 10-31 에 쟀다 → "사후 발견 + 사전 계획한 기술적 확인"으로 쓸 수 있다. 검정 규칙(유의수준)은 정하지 않았으므로 "판정"이라 부르지는 않는다.
- ✅ 쓸 문장: "캐스케이드는 시험 요청의 0.7~0.8% 만 넘기면서 SQLi 를 CmdI 로 잘못 경보하던 건수를 36~55% 줄여, CmdI 경보 정밀도를 93.9~95.2% 에서 97.1~97.3% 로 높였다(두 seed). CmdI F1 은 네 seed 모두 올랐다."
- ❌ "SQLi–CmdI 혼동을 해결했다"(seed 42 는 123건 남음) · "캐스케이드가 공격을 더 잘 막는다"(차단 실패 감소는 부차적) · "정상 오탐도 줄였다"(늘었다, §1).

### B. (주 기여 근거) 128 토큰 제한이 CmdI 구분을 무너뜨린다 — E12

| | seed 42: 512 → 128 | seed 43 |
|---|---|---|
| Macro-F1 (사전 판정 E12-1) | 0.9914 → 0.9718 (**−1.96%p, p 0.006**) | 0.9947 → 0.9777 (**−1.70%p, p 0.006**) |
| CmdI F1 | 0.9784 → **0.9038** | 0.9903 → **0.9284** |
| SQLi → CmdI | 99 → **847** | 2 → **551** |
| 잘린 행 정답률 (안 잘린 행은 0.1%p 이내) | 0.994 → 0.957 | 0.996 → 0.956 |

- 128 토큰에서 잘리는 비율: 전체 6.9% · **CmdI 26.5%** · CodeInjection 24.7% — 주입 클래스에 몰린다.
- 이것이 A 의 **메커니즘 증거**다: 문맥을 자르면 정확히 SQLi→CmdI 오탐이 폭증한다 → "공격 종류 구분에는 긴 문맥이 필요하다"는 가설과 방향이 맞는다(가설 사전 기록: 05 §3.4).
- 선행 연구(WAMM'25)의 원 설정 그대로면 char-CNN 단독보다도 낮다 → 선행 연구 대비 **약점 지적**으로 쓸 수 있다("개선"이 아니라 "설정의 한계 발견").
- ✅ "원 논문 설정(128 토큰) DistilBERT 는 주입 요청의 약 25% 를 잘라 CmdI 구분을 잃고, 이 데이터에서 char-CNN 단독보다도 낮았다."
- ❌ "캐스케이드가 원 논문 모델보다 67~76배 빠르고 정확하다"(그 운영점은 넘김 0% — char-CNN 단독과 같은 말).

### C. (주 기여 근거) 오류 구조 진단 — 어려움은 공격 "여부"가 아니라 "종류"

- 모델·입력과 무관하게 최약 클래스는 CmdI: TF-IDF 0.785 · RGB CNN 0.757 · char-CNN 0.962~0.968(05 §3.3). ⚠️ 논문에는 RQ1 제외 결정상 RGB 값을 빼고 TF-IDF(비교 기준)·char-CNN·DistilBERT 값만 쓴다.
- DistilBERT 로 바꿀 때 차단 실패는 두 seed 모두 **약 7%** 만 줄고, 공격 종류 혼동은 **37~84%** 줄었다(§8.36).
- CmdI 는 풀의 2.1%(SQLi 의 1/33)·템플릿 공유 14.7%(다른 클래스 60~71%) — 외워서 맞히기 어려운 소수 고위험 클래스(§8.27).
- Macro-F1 은 CmdI 오답 1건 수정의 이득이 SQLi·Normal 의 약 6배 → 전체 지표 차이의 대부분이 CmdI 에서 나온다(§8.7).
- 활용: 서론 문제 제기("왜 공격 종류 구분이 문제인가")와 "왜 전체 Macro-F1 차이는 작아 보이는가"의 답.

### D. (보조) 그 개선을 싸게 얻는다 — 속도

| 구성 | 기준 대비 | 판정 | 출처 |
|---|---|---|---|
| char-CNN → DistilBERT (B0) | DistilBERT 단독보다 합산 **12.3배**(s42) · **10.6배**(s43) | F1 조건은 s42 만 통과(1/2), 4 seed 중 3 seed 0.3%p 이내 | §8.34·§8.35·§8.40 |
| k3 출구 → DistilBERT (E14) | 주 캐스케이드 대비 **×2.40 · ×2.27**(23.8~29.3배) | 사전 판정 **2/2 통과** | §8.38 |
| char-CNN-EE (DL-C) | char-CNN 단독 대비 3.52~3.62배 | 사전 판정 2/2 통과 — 단 넘김이 아니라 "결합 학습 압축" | §8.32·§8.33 |

- 서술 위치를 바꾼다: 이전 원고의 헤드라인 → **"A 의 개선을 실시간 경로에 둘 수 있는 비용"**으로 격하. 이러면 DL-A seed 43 재현 실패(−0.32%p)의 무게도 줄어든다(주장이 "DistilBERT 와 같은 정확도"가 아니라 "CmdI 오탐을 싸게 줄인다"로 바뀌므로).
- ⚠️ 투고 검토 🔴3: `k3 exit → DistilBERT`(seed 42)는 char-CNN 단독에 지배된다(F1 0.9883 vs 0.9884, 지연 ~1.57 vs 0.604ms). 이 구성의 CmdI 정밀도는 **문서에 없다** — 측정 전엔 "CmdI 오탐 개선 구성"으로 권하지 말 것(§3).

### E. (보조) 배포 조건 평가 방법

- 실사용자 정상 층 분리: char-CNN 의 실사용자 FPR 이 스캐너 층의 약 8배(2.73% vs 0.36%, E2 char-CNN). 딥러닝 캐스케이드에서도 단일 τ 가 실사용자 정상을 33.6% 넘긴 fold 가 있었다(A2, §8.39) → 층을 나누지 않으면 배포 비용을 과소평가한다.
- 배수 평균은 조화평균(산술 51.6배 → 합산 12.3배 정정 사례, DL-A).
- ⚠️ §8.43 조건 2: H-G4(+24.9%p)·E1 공정 지연 철회(0.27배)·게이트 test 넘김률 함정(H-G2c·H-G3F)은 **RGB 1차에서 잰 값**이라 논문 근거로 옮겨 쓰지 않는다. 쓰려면 "방법(식·절차)"만 기여로 쓰고 수치는 딥러닝 구성 값(위 두 줄)으로 댄다.
