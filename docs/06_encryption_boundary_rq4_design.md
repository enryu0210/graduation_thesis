# Phase 6 — 암호화 경계 설계/결정 문서 (RQ4: 내용 기반 탐지의 한계와 신호 이동)

> 이 문서는 사람이 읽는 **설계·의사결정 기록**입니다.
> 실제 수치는 (구현 후) `experiments/results/rq4_*.json` 과 `docs/figures/rq4/` 에서 확인하세요.
> 착수 배경: 2026-07-09 교수 미팅. 매주 월 15:00 미팅(단, 다음 회는 7/14 화).

RQ4: *"탐지 신호가 콘텐츠에서 사라질 때(인코딩→암호화), 바이트-이미지 CNN의 내용 기반
탐지는 어디서 원리적으로 붕괴하며, 탐지를 유지하려면 신호는 어디로 이동해야 하는가?"*

---

## 0. 왜 이 RQ인가 — 교수 지적과 우리의 재해석

### 0.1 교수 미팅 지적 (2026-07-09)
1. 현재 주제(웹 공격 페이로드 이미지화 CNN)는 **이미지 변환 선행연구가 이미 많아 신규성이 약하다.**
2. 논문이 되려면 둘 중 하나: **(a) 정확도가 낮아지더라도 기존이 탐지 못하던 것을 탐지**하거나,
   **(b) 여러 방법을 시도해 성능 개선이 있는 방법을 채택**해야 한다.
3. 제안: **암호화된 통신 상에서도 페이로드를 탐지할 수 있는지** 병행 연구.

### 0.2 교수 제안의 함정 — 그대로 받으면 안 되는 이유 ⚠️
현재 파이프라인의 본질은 **바이트 → 이미지로 페이로드의 *내용*(SQLi/XSS/CmdI)을 식별**하는 것이다.
그런데 TLS 등으로 암호화되면 그 바이트는 **고엔트로피 랜덤 암호문**이 된다.
`' OR 1=1` 이든 `<script>` 든 암호화 후에는 통계적으로 난수라 **서로 구분 자체가 불가능**하다.
→ "암호화된 상태로 페이로드 *내용*을 읽는다"는 명제는 **원리적으로 성립하지 않는다.**

문헌에서 "암호화 트래픽 탐지"는 항상 셋 중 하나를 의미한다:

| 해석 | 무엇을 보나 | 우리 연구에의 신규성 |
|---|---|---|
| **(A) Side-channel 흐름 분류** | 복호화 없이 패킷 크기·타이밍·흐름 통계·암호문 바이트 분포(FlowPic, Deep Packet, USTC-TFC2016) | 있음 — 단 "악성 흐름 여부"만, SQLi vs XSS 구분은 못 함 |
| (B) WAF가 TLS 종료 후 평문 검사 | 지금과 동일한 평문 페이로드 | **없음**(기존 문제 반복) |
| (C) 흐름/세션 단위 악성 탐지 | 흐름 행동 패턴 | 있음, (A)와 유사 |

교수가 참고로 준 `docs/thetics/` PDF 2편도 이 라인이다:
- **s42400-023-00170-z** (Springer *Cybersecurity*): Cobalt Strike 비콘 트래픽을 이미지화한 파일리스
  악성코드 탐지 — 설계문서 §10에 이미 "본 연구와 가장 근접한 선행"으로 기록. → (A)/(C).
- **시그니처 기반 필터링 + 2D-CNN 하이브리드 악성 트래픽 탐지**(국문): 시그니처 1차 필터 + 흐름
  2D-CNN → (A)/(C).

> 즉 교수의 실제 의도는 *"암호문 속 내용을 읽어라"*가 아니라 **"네 이미지화 기법을 암호화
> 트래픽(흐름 단위)으로 확장하라"** 에 가깝다.

### 0.3 우리의 재해석 — 모순을 *발견*으로 전환 (프레이밍 C, 2026-07-09 확정)
"암호화하면 내용 탐지가 불가능하다"는 **부정적 결과**는, 교수의 요구 (a)("정확도가 낮아지더라도
기존이 못하던 것")와 오히려 정확히 맞물린다. RQ4를 다음 한 문장으로 세운다:

> **내용 기반 이미지 탐지(RQ1)는 강력하지만 암호화라는 경계에서 원리적으로 붕괴한다. 실무에서
> 탐지를 유지하려면 탐지 신호가 콘텐츠에서 흐름 side-channel으로 이동해야 하며, *동일한
> 이미지화 패러다임*이 그 전이를 담을 수 있다.**

이로써 논문 축이 완성된다:
`RQ1(내용 탐지 성능) → RQ2(회피 취약성) → RQ3(방어 트레이드오프) → RQ4(암호화 경계와 신호 이동)`.

## 1. 두 개의 하위 실험 (RQ4a / RQ4b)

### RQ4a — 콘텐츠 신호 소멸의 정량화 (원리 증명, **새 데이터 불필요**)
현재 `payload_4class` test 페이로드를 **표현 은닉 강도 스윕**으로 변환하고, 각 단계에서 세 지표를 측정한다.

**변환 스윕(엔트로피 증가 순)**
| 단계 | 변환 | 바이트 성격 |
|---|---|---|
| S0 | raw (평문) | 구조적 저엔트로피 |
| S1 | URL/HTML 인코딩 (RQ2 재사용) | 표면형 교란, 여전히 저엔트로피 |
| S2 | Base64 | 문자셋 축소·재배치, 중엔트로피 |
| S3 | 반복키 XOR / 약한 난독화 | 준랜덤 |
| S4 | AES-CBC/CTR (완전 암호화) | 고엔트로피 난수(≈8 bit/byte) |

**측정 지표(각 단계마다)**
1. **바이트 엔트로피**(Shannon, payload별 평균) — 표현이 얼마나 "내용을 감췄나"의 물리량.
2. **클래스 분리도** — 이미지 표현 공간에서 4클래스가 얼마나 구분되나
   (예: 클래스 평균 이미지 간 L2 거리, 또는 픽셀 히스토그램의 클래스 간 JS-divergence).
3. **탐지 성능** — RQ1에서 학습한 CNN을 **재학습 없이** 각 단계 이미지에 그대로 추론한 Macro-F1.
   (선택) 각 단계에서 재학습했을 때의 상한도 함께 — "재학습해도 못 넘는 벽"을 보이기 위함.

**가설 H4a**: 엔트로피↑ → 클래스 분리도↓ → 탐지 성능이 **랜덤 기준선(1/클래스수 ≈ 0.25)** 으로 수렴.
S4(완전 암호화)에서 Macro-F1 ≈ 랜덤이면 "암호화 지점에서 내용 기반 탐지는 원리적으로 불가능"을
**곡선 하나로 증명**한다. 이것이 이 논문의 방법론적 정직성이자 핵심 그림(entropy–separability–F1 3축).

> 이 실험은 데이터셋 추가 없이 **현재 파이프라인(preprocess → payload_to_image → 학습된 CNN)**
> 만으로 가능하다. 변환은 순수 문자열/바이트 함수(`src/attacks` 재사용 + 암호화 유틸 추가).

### RQ4b — 신호의 이동: 흐름(side-channel) 이미지 탐지 (소규모 실측)
내용이 사라져도 **흐름 수준 신호**(패킷 크기 시퀀스·바이트 히스토그램·타이밍)는 남는다.
공개 암호화 트래픽 데이터의 **일부**를 flow→image로 변환해 **같은 CNN 구조**로 악성/정상 흐름을 탐지.

- **데이터 후보**: `USTC-TFC2016`(악성/정상 트래픽, 이미지화 선행 다수) 1순위,
  대안 `ISCX-VPN-nonVPN` / `CIC-IDS2017`. → 확정은 1절 아래 "열린 결정".
- **흐름 이미지화**: FlowPic류(패킷 크기×시간 2D 히스토그램) 또는 앞 N바이트 flow→image.
  RQ1의 `side=48` 이미지 규격을 최대한 재사용해 "동일 이미지화 패러다임" 서사를 유지.
- **과제 재정의(정직성)**: 이건 payload_4class 와 **다른 데이터·다른 단위(흐름)** 다. 따라서
  "SQLi/XSS 구분의 연속"이 아니라 **"탐지 가능성의 재획득 — 악성 흐름 여부"** 로 명확히 서술한다.
  같은 4클래스로 억지 매핑하지 않는다.

**가설 H4b**: 내용은 못 봐도 side-channel image로 악성 암호화 흐름은 유의미하게 탐지 가능
→ "탐지 신호가 콘텐츠에서 흐름으로 이동"을 실측으로 완성.

## 2. 위협 모델 / 스코프 — 심사 방어용 못 박기

- **관찰 지점**: RQ4a의 "암호화 페이로드"는 *네트워크 미들박스가 TLS 종단 이전의 암호화
  바이트를 본다*는 상황을 모델한다(엔드투엔드 TLS면 WAF도 못 보므로 그 자체가 "경계"의 정의).
- **RQ4a의 성격**: 특정 공격이 아니라 **표현 은닉이 탐지 가능성에 미치는 상·하한 분석**.
  실측 곡선이 곧 결론이며, "완전 암호화 시 내용 탐지 불가"는 회피가 아니라 **정보이론적 한계**.
- **RQ4b의 성격**: 별도 데이터의 **악성 흐름 이진 탐지**. 본 논문 페이로드 4클래스 과제와
  분리해 보고하고, 연결고리는 "이미지화 패러다임의 이식성"으로만 삼는다.
- **명시적 한계(논문 필수 서술)**: (1) 완전 TLS에서는 내용 탐지가 원리적으로 불가 — 이것이 발견이지
  결함이 아님. (2) RQ4b는 데이터·단위가 달라 RQ1 수치와 직접 비교 불가.

## 5. 리스크 / 열린 결정
- [ ] **RQ4b 데이터셋 확정**: USTC-TFC2016 vs ISCX vs CIC-IDS2017 (용량·라이선스·전처리 난이도).
- [ ] **논문 응집성 리스크**: RQ4b가 별도 데이터·단위 → "곁가지"로 보일 수 있음.
  → 프레이밍 C("신호 이동")가 이 봉합의 유일한 근거. 서론·결론에서 이 축을 반복 강조.
- [ ] **RQ4a "재학습 상한"을 넣을지**: 추론만 vs 각 단계 재학습. 재학습해도 S4에서 못 넘는 벽을
  보이면 훨씬 강하지만 비용 증가.
- [ ] **엔트로피와 탐지의 인과 서술**: 상관을 인과로 과장하지 않기 — "클래스 분리도"라는 매개
  지표를 함께 보고해 인과 사슬(은닉→분리도↓→F1↓)을 명시.
- [ ] **RQ3(방어)와의 순서**: RQ4는 RQ3 이후 배치(현 구조 유지). 단 RQ2/3 미완이면 RQ4a
  파일럿(추론만)은 병렬 착수 가능.
- [ ] (운영) 브랜치 여전히 `phase1-data-acquisition` 에 전 Phase 누적 — 정리 미정.

## 6. 요약 — 이 문서가 확정한 것
1. 교수 제안을 **재해석**: "암호문 내용 읽기"(불가능)가 아니라 **"암호화 = 내용 탐지의 경계"** 로.
2. RQ4 = **RQ4a(신호 소멸의 정량 증명, 새 데이터 불필요)** + **RQ4b(흐름 이미지로 신호 이동 실측)**.
3. 핵심 그림: **entropy–separability–F1 스윕 곡선** — 암호화 지점에서 Macro-F1→랜덤 수렴.
4. 정직성: 완전 암호화 시 내용 탐지 불가는 *발견*이며, RQ4b는 별도 과제로 분리 서술.
5. 7/14 준비: 1페이지 요약 + RQ4a 파일럿 곡선(현 파이프라인으로 가능) + flow 데이터셋 점검.
