다섯 줄 요약 — 논문의 전체 이야기
  1. 출발은 음성 결과입니다. 이미지화 CNN 단독은 텍스트 모델에 유의하게 집니다 (char-CNN MCC 0.9944 vs RGB CNN 0.9762, 5-fold CV + Holm 보정 adj p = 0.0010~0.0247). 대신 처리량이 13.6배 우위입니다. 즉 이기는 축은 정확도가 아니라 비용이었습니다.
  2. 그래서 제안 모델을 캐스케이드로 바꿨습니다. 1차 RGB CNN 이 전량을 보고, 확신도가 τ 미만인 소수만 2차 char-CNN 으로 올립니다. 트래픽의 8.0%만 올려 char-CNN 급 정확도를 유지하면서 지연을 5.07배 낮췄고, 추가 학습은 0입니다(기존 체크포인트 2개의 조합).
  3. 구조를 바꾸자 단일 모델에서는 존재하지 않던 축 두 개가 드러났습니다. 정확도가 아니라 지연을 표적으로 하는 비용 기반 공격(에스컬레이션 2.17배, SLA 붕괴)과, 방어의 대가가 정확도가 아니라 지연으로 지불된다는 현상(esc 34.97% → 69.52%)입니다.
  4. 방어 실험의 헤드라인은 학습형 방어의 패배입니다. 미지 변형 조건에서 학습 8셀짜리 적대적 증강을 학습이 0인 입력 정규화가 이깁니다(RGB CNN 0.2112 vs 0.4693/0.5704).
  5. Phase 12 확장 3안 중 논문의 주장을 키운 것은 하나뿐이며, 부정 결과 2건을 그대로 싣습니다. 인코딩 불변 채널은 단독으로는 실패했지만 증강과 결합하면 미지 변형 일반화를 10.9% → 69.2% 로 올려 이 프로젝트에서 가장 아팠던 음성 결과(F9)를 부분적으로 뒤집었습니다.

2. 제안 방법 — 왜 '특징 융합'이 아니라 '캐스케이드'인가 (논문 3장)

2.1 가장 중요한 설계 결정

"하이브리드"라고 하면 보통 two-branch 특징 융합을 떠올립니다(이미지 CNN 특징 ⊕ char-CNN 특징 → concat → FC). 그러나 이 구조는 모든 입력이 두 브랜치를 전부 통과하므로 비용이

C_fusion = C_cnn + C_charcnn        ( > char-CNN 단독 )

이 되어 애초 목표였던 RGB CNN 의 속도 우위가 사라집니다. 정확도만 얻고 속도는 잃으며, 심지어 char-CNN 단독보다 느립니다(실측 0.0627 ms vs 0.0561 ms). → 채택하지 않습니다. 대신 선택적 실행(cascade) 을 택합니다.

C_cascade = C_cnn + r · C_charcnn    ( r = 에스컬레이션 비율 )

r 이 작으면 정확도는 char-CNN 급, 지연은 CNN 급이 됩니다. τ 를 움직이면 정확도–지연 곡선이 그려지고, 양 끝점은 정확히 두 단독 모델입니다 — τ→0 은 얕은 CNN 단독, τ>1 은 char-CNN 단독. 이 성질은 단위 테스트로 고정했고 실측으로도 확인했습니다(τ=0 → esc 0.0000 / F1 0.9676, τ=1.01 → esc 1.0000 / F1 0.9954).

학습은 하지 않습니다. Phase 4/5 에서 이미 학습한 체크포인트 2개를 그대로 조합합니다 → 추가 GPU 학습 비용 0, 그리고 "같은 모델을 배치 방식만 바꿨다"는 인과가 성립합니다.

2.2 공정성을 지키는 세 가지 못 (논문 4장 실험환경)

  1. τ 는 반드시 val 에서 고른다. test 로 고르면 임계값이 test 에 과적합돼 성능이 부풀려집니다(정보 누수). val 스윕으로 τ 를 확정한 뒤 test 에 한 번만 적용합니다. 선택 규칙은 match-teacher(val Macro-F1 이 char-CNN 이상이 되는 τ 중 에스컬레이션 최소)와 budget(에스컬레이션 ≤ 예산 아래 val Macro-F1 최대) 2종입니다.
  2. 비교 기준선 4종을 같은 test·같은 지표로 함께 낸다 — 1차 단독 / 2차 단독 / 융합형 비용선 / oracle 라우팅(1차가 틀린 샘플만 정확히 넘겼을 때의 상한). oracle 은 게이트 품질을 재는 자로 쓰입니다.
  3. 지연은 두 모델을 같은 기준으로 잰다. warmup 후 5라운드 × 20회의 중앙값, CUDA 는 synchronize() 필수. 모델 순전파 기준이며 전처리는 제외(µs 수준이라 결론 불변).
⚠️ 이 못이 실제로 필요했던 사례 — 논문 4장에 재현성 항목으로 씁니다. 1차 측정에서 char-CNN 지연이 같은 조건인데도 0.0555~0.0904 ms 로 튀어 특정 arm 의 speedup 이 9.30배로 부풀려졌습니다(재측정 7.05배). 원인은 단발 측정(warmup 3 · repeats 10)이 GPU 클럭 부스트 상태와 타 프로세스 간섭을 그대로 받은 것이었습니다. 5라운드 × 20회 중앙값으로 바꾼 뒤 변동은 0.7% 이내입니다. 헤드라인이 속도인 연구에서 지연 측정의 분산 관리는 정확도 지표만큼 중요합니다.

정확도뿐 아니라 비용에서도 RGB 가 이깁니다. char-CNN 급 정확도에 도달하는 데 gray 는 78.4% 를 넘겨야 했지만 RGB 는 27.7% 로 충분했습니다(1차가 정확할수록 넘길 일이 줄어 캐스케이드 전체가 싸집니다). 우려했던 FPR 열세는 운영점에서 재현되지 않았습니다(양쪽 모두 0.0014). gray 의 실패는 규칙 탓이 아니라 1차 모델의 확신도 품질 탓이며 — 이 구조의 성패는 게이트 품질이 좌우한다는 사실을 그대로 보여줍니다(gray match-teacher 의 speedup 은 1.11배로, 캐스케이드를 쓸 이유가 사라집니다).

4. RQ2 — 회피 강건성과 비용 기반 공격 (논문 5장)

4.1 위협 모델과 공격 설계

블랙박스 · 모델 무관 · 의미보존 표면 변형만 사용합니다. feature-space 와 problem-space 를 구분하며 problem-space 가 주 실험입니다 — 주석 삽입 /**/, 대소문자 랜덤화, 공백/탭 치환, URL/이중 인코딩, 동치 SQL 토큰 치환, XSS String.fromCharCode 등 14종을 누적 k=1..5 로 적용합니다. 생성된 변형은 실제로 동작하는 페이로드입니다.

주 지표는 any-misclass(변형 하 오분류율)입니다. 원래 주 지표였던 benign-evasion(공격 → Normal)은 5모델 전부 ~0(0.0000~0.0022)이라 판별력이 없기 때문입니다(F8). 이 교체는 방어 실험을 돌리기 전에 문서로 고정했습니다.

⚠️ any-misclass 를 주 지표로 삼는 것의 정당성 — 심사에서 반드시 나올 질문입니다. any-misclass 는 WAF 우회가 아닙니다(SQLi → XSS 로 틀려도 탐지·차단은 됩니다). 근거 3개를 미리 세워 둡니다.
  1. 운영 비용이 실재합니다. 공격 유형은 대응 playbook · 차단 규칙 · 포렌식 분류를 가릅니다. SQLi 를 XSS 로 라벨링하면 잘못된 대응이 자동 실행됩니다 — 탐지는 되지만 대응이 틀립니다.
  2. 결정 경계 불안정성의 프록시입니다. 의미보존 표면 변형에 예측이 흔들린다는 것은 그 표현이 표면 토큰 shortcut 에 의존한다는 직접 증거이며, 더 강한 공격에 대한 선행 취약 지표입니다.
  3. 유일하게 변별력이 있는 강건성 축입니다(모델 간 2.6배 차이).

한계도 같은 문단에 씁니다 — 이 축의 주장은 "표현 안정성을 얼마의 비용으로 살 수 있는가"이지 "WAF 가 더 안전해졌다"가 아닙니다.

6.4 M4 — 다단 조기종료: 미채택 (부정 결과, 논문에 그대로 싣습니다)

착안: 캐스케이드 비용식 C(r) = C_cnn + r · C_charcnn 에서 지금까지의 모든 논의는 r 만 건드렸고 C_cnn 은 상수로 뒀습니다. 게이트를 완벽히 고쳐도(oracle r=1.87%) 7.29배가 천장이고 그 원인은 C_cnn 이 바닥이기 때문입니다. 1차 CNN 내부에 조기종료 헤드를 달아 그 천장을 깨려 했습니다. 마스킹이 아니라 축소 배치로 구현했습니다(그래야 지연이 실제로 줍니다. 근거는 eval 모드 BatchNorm 이 running stats 를 쓴다는 것이며, 단위 테스트로 고정했습니다).

H7-2 는 이 하드웨어에서 어떤 임계값으로도 도달 불가능했습니다. 6.5배가 되려면 C_cnn 을 −53% 해야 하는데, 조기종료의 이론적 바닥(정확도를 완전히 포기한 1블록 CNN)조차 −46% 입니다. 실패는 임계값을 잘못 골라서가 아니라 비용 바닥이 목표 위에 있어서이며, 스윕해도 뒤집히지 않습니다.

논문 서술: "조기종료가 무용하다"가 아니라 "얕은 CNN 1차는 GPU 에서 이미 바닥이라 더 뺄 것이 없다"로 씁니다. 이는 기여 C1(1차가 이미 충분히 싸다)의 근거를 오히려 강화합니다. 선행 연구(ACM SAC 2025 early-exit IDS 등)가 조기종료로 이득을 본 것은 CPU/엣지 배포나 1차가 훨씬 큰 모델(BERT 급)의 영역입니다.

  • F12 — 단계적 신호 소멸 실험(평문 → 인코딩 → 고정키 XOR → AES)에서 고정키 XOR 은 F1 0.9445 를 유지하다가 AES 에서 0.3965 로 붕괴합니다. → 탐지를 죽이는 것은 엔트로피가 아니라 키 랜덤화입니다.
  • ⚠️ 초점 재조정: "신호가 흐름으로 이동한다"는 결론은 선행이 이미 도달해 있습니다 (Kutlimuratov et al. 2026 은 처음부터 흐름 메타데이터만 사용, 470k req/s). → 우리 기여는 도착지가 아니라 경계의 정량 증명(F12) 으로 좁힙니다.
  • G6 미결 — RQ4b(USTC-TFC2016 흐름 트랙)는 F1 0.9999 로 포화되어 판별력이 없습니다. 부록 강등 vs host 단위 분할 재실험은 교수님 확인이 필요한 항목입니다.

11. 정직하게 함께 쓸 한계 (논문 7장)

  1. 이미지 단독은 텍스트 모델에 유의하게 진다(F1).
  2. clean 탐지 상보성 이득 없음(F4) — 캐스케이드의 기여는 탐지집합 확장이 아니라 비용 축소다.
  3. 적대적 증강은 본 변형만 암기하며(F9), 그 정도는 표현에 의존한다.
  4. 소규모 배포에서는 char-CNN 단독으로 충분하다 — 캐스케이드가 필요한 것은 고처리량 환경이다.
  5. 적응형 공격 미수행(G4) — 방어를 알고 재설계된 공격은 다루지 않았다. 방어 논문의 표준 비판 지점이므로 명시한다.
  6. 성능 차이는 표면 토큰 포화 상태의 트랙에서 측정됐다.
  7. 조기종료 1차(M4)는 시도했으나 미채택 — 얕은 CNN 1차는 GPU 에서 이미 커널 런치 병목이라 연산을 18% 생략해도 시간이 6% 늘었다. ViT/hybrid 와 같은 성격의 정직한 부정 결과이며, C1 의 근거를 오히려 강화한다.
  8. 적대적 증강 방어를 켜면 C5 의 불일치 신호가 지워진다(ROC-AUC 0.764 → 0.598) — RQ3 방어와 RQ6 부가 능력은 서로를 잡아먹는다.
  9. 인코딩 불변 채널(M2)은 단독으로는 회피를 오히려 쉽게 만든다(0.5981 → 0.6550) — clean 학습셋에서 이 채널이 기존 채널과 다른 픽셀은 0.20%뿐이라 증강 없이는 모델이 쓸 줄 모른다. "불변성을 표현에 넣으면 공짜로 강건해진다"는 직관에 대한 반례다.
  10. M2 를 켜면 비용 기반 공격(C3)의 표면이 넓어진다 — 공격 하 에스컬레이션 35.39% → 77.71%. 강건성과 지연이 정면으로 상충한다.
  11. 캐스케이드 norm(B안) 판본은 미측정 — M2 vs B안의 캐스케이드 수준 직접 대조는 불가능하며, 위 비교는 단일 RGB CNN 기준이다.
  12. 단일 CNN ρ0.5 의 H6-1 41.6% 가 경계 밴드(40~50%) 안이다 — 강한 주장이 필요하면 5-fold CV 재판정이 필요하다.
  13. RQ4b(흐름 트랙)는 포화(F1 0.9999)로 판별력이 없다 — 부록 강등 여부는 미결(G6).
