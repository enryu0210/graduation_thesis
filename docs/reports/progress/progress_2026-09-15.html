웹 공격 문자열을 이미지로 바꿔 탐지하는 2단 구조 연구

텍스트 모델로 입력 필드 실험을 마무리하고, 실사용자 정상 요청의 오탐률을 처음 실측한 결과
보고일 2026-09-15 · 보고 범위 2026-09-14 ~ 2026-09-15 (직전 보고 이후분)
세 줄 요약
  1. 입력 필드 실험 완료 — 지난 보고에서 미실행이던 텍스트 모델(문자 단위 CNN)을 같은 조건으로 돌렸습니다. 텍스트 모델은 조합 간 차이가 0.3%p 이내라 규칙상 "URI+본문"을 골랐고, 미리 정한 규칙(두 모델이 갈리면 이미지 모델을 따름)대로 학습 데이터 입력은 "URI+본문+쿠키"로 확정합니다. 텍스트 모델도 이 입력에서 손해가 없습니다.
  2. 실사용자 정상 요청의 오탐률을 처음 실측했습니다 — 실사용자 2.73% vs 스캐너 0.36%(약 8배). 지난 보고의 한계("정상 = 스캐너 탐색 요청 위주")가 수치로 확인됐고, 오탐률은 반드시 출처별로 나눠 보고하겠습니다.
  3. 평가 지표 정비 — 선행연구 대조에서 나온 권고(교정 지표·유병률 병기·효율 점수·신뢰구간)를 반영하고, 회피 실험 지표를 문헌 용어(ASR·AUA)에 맞췄습니다. 지난 보고의 수치 하나(실사용자 요청 수)도 정정합니다.

1. 지난 보고 정정

지난 보고 6절에서 "실사용자 브라우저에서 온 정상 요청은 고유 3,666개"라고 썼는데, 이 숫자는 라벨 오류 감사로 걸러낸 요청(실제 공격 30,280건)을 빼기 전에 센 값이었습니다. 학습 데이터 기준으로 다시 세면 아래와 같습니다.

결론 방향은 같고 오히려 더 강해졌습니다. 다만 시험 데이터의 실사용자 요청은 95개뿐이라, 오탐이 0건이어도 95% 신뢰구간 상한이 약 3.9%입니다. 이 해상도로는 "실사용자에게 오탐이 낮다"는 주장을 할 수 없습니다.

쉽게 말하면 정상 요청 약 6.7만 개 가운데 "진짜 사람이 브라우저로 보낸 요청"은 100개 중 1개꼴입니다. 나머지는 공격 도구(스캐너)가 사이트를 훑으며 보낸 평범한 요청이라, 모델은 사실상 "스캐너의 공격 vs 스캐너의 탐색"을 구분하는 법을 배웁니다.

2. 입력 필드 실험 — 텍스트 모델 결과

지난 보고와 똑같은 분할(시험 데이터 봉인, 학습+검증 226,048건, 5겹 교차검증)과 똑같은 채택 규칙을 적용했습니다. 두 모델이 같은 분할을 공유하므로 모델 간 비교도 대응표본으로 성립합니다. GPU 약 3시간.

3. 정상 요청의 출처별 오탐률 (첫 실측)

실사용자 요청의 오탐률이 스캐너 요청의 약 8~11배이고 신뢰구간도 겹치지 않습니다. 전체 오탐률 0.3%대는 정상 요청의 96%를 차지하는 스캐너 탐색 요청이 만든 숫자입니다. 논문에서는 전체 오탐률을 "실운영 오경보율"로 쓰지 않고, 실사용자 층 수치를 반드시 함께 싣겠습니다. (이미지 모델은 이 기록 기능을 넣기 전에 실행해 출처별 수치가 없습니다. 본 측정에서 함께 냅니다.)

4. 평가 지표 정비

선행연구 대조에서 나온 지표 권고를 GPU 재측정 전에 반영했습니다(지표가 빠진 채 돌리면 학습을 다시 해야 하므로).

추가·변경이유
Brier 점수 (교정 지표)기존 교정 오차(ECE)는 구간 나누기에 값이 좌우됩니다. 교정을 보고하는 인접 연구 2편이 모두 Brier를 씁니다.
PR-AUC 에 유병률 병기PR-AUC는 공격 비율에 직접 의존합니다. 시험 데이터의 공격 비율(74.8%)을 함께 적고, 드문 쪽인 정상을 양성으로 본 값도 냅니다.
효율 점수(FE)2단 구조와 가장 가까운 선행연구(Tasdemir 2023)가 실제로 쓰는 지표라 비교에 필요합니다.
부트스트랩·Wilson 신뢰구간표본이 작은 평가(실사용자 층, 라벨 오류 공격 세트)에서 구간을 함께 보고하기 위해서입니다.
회피 실험: ASR 명확화 + AUA·AMB 신설문헌의 공격 성공률(ASR)은 "공격이 정상으로 통과한 비율"입니다. 기존 결과에서 ASR은 전 구간 0이었지만, 공격 하 정확도(AUA)는 0.997 → 0.658로 떨어졌습니다. 둘을 함께 실어야 "탐지 우회에는 강하지만 공격 종류 판정은 무너진다"가 드러납니다. AMB는 회피에 성공하는 데 필요한 최소 변형 수(공격자 비용)입니다.
쉽게 말하면 공격 문자열을 조금씩 바꿔(예: OR → oR, 공백 → 주석) 모델을 속여 보는 실험에서, ASR 은 "바뀐 공격이 정상으로 통과한 비율", AUA 는 "바뀐 공격의 종류까지 맞힌 비율"입니다. 기존 결과는 통과는 한 건도 없었지만(ASR 0) 종류 판정은 99.7% → 65.8% 로 무너졌습니다 — 막기는 막는데 "무슨 공격인지"는 헷갈린다는 뜻입니다. ASR 만 보고하면 "아무 문제 없음"으로 읽히므로 두 값을 함께 싣습니다.

5. 기타 준비 작업

  • "방화벽 규칙을 통과한 실제 공격" 평가 세트 구성 — 라벨 오류 감사로 걸러낸 30,280건을 평가용으로 정리했습니다. 이 중 760건은 학습 데이터의 SQL 주입 요청과 문자열이 완전히 같았습니다(같은 공격이 원본에 한 번은 정상, 한 번은 SQL 주입으로 기록). 라벨 오류라는 독립 방증이지만 모델이 학습 때 이미 본 문자열이므로, 탐지율 헤드라인은 겹치지 않는 요청으로만 내고 겹친 760건은 따로 적기로 측정 전에 정했습니다.
  • 2단 구조 판정 신호 비교 도구 — 1차 모델이 2차로 넘길지 정하는 신호(최대 확률, 온도 보정 확률, 1·2위 차, 엔트로피)를 비교하는 도구를 먼저 만들었습니다. 측정은 입력 전환 후입니다.
  • 데이터셋 원 논문 2편 확보 — 주 데이터셋 논문(2022)과 외부 검증 데이터셋 논문(2025) 원문을 받아 대조하다가, 참고문헌 목록에 적어 둔 저자명 오류(실존하지 않는 저자)를 발견해 고쳤습니다.

6. 다음 계획

  1. 학습 데이터 입력을 "URI + 본문 + 쿠키"로 전환하고, 쿠키를 비운 입력으로 이미지 모델의 쿠키 이득이 지름길인지 확인
  2. 입력 전환 후 전 모델(이미지·텍스트·2단 구조)을 시험 데이터로 본 측정 — 출처별 오탐률 포함
  3. 2단 구조 판정 신호 비교, "방화벽 규칙을 통과한 실제 공격" 세트 탐지율 측정

7. 여쭙고 싶은 것

Q1실사용자 오탐률을 무엇으로 보고할까요?

시험 데이터의 실사용자 요청은 95개뿐이라 신뢰구간이 넓습니다. (가) 시험 데이터 값을 주 수치로 쓰고 구간과 한계를 명시한다 / (나) 교차검증 5겹 합산(550건)을 주 수치로 쓰고 시험 데이터 값을 병기한다. (나)가 해상도는 높지만 입력 선택에도 쓰인 데이터라, 저희는 (가)를 기본으로 두고 (나)를 보조로 싣는 안을 생각하고 있습니다.

Q2쿠키 확인 실험에서 지름길로 나오면

쿠키를 비웠을 때 이미지 모델 성능이 "URI + 본문" 수준으로 떨어지면, 쿠키 이득은 내용이 아니라 존재 여부 신호로 봐야 합니다. 그 경우 입력을 "URI + 본문"으로 되돌리는 것(사전 규칙의 예외)과, 채택은 유지하고 한계로만 적는 것 중 어느 쪽이 적절할지 의견을 여쭙고 싶습니다.
